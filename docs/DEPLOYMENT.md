# 本机生产运行与恢复

本批补齐运行基础，仍只监听 `127.0.0.1`。没有远程身份认证，不要直接公开端口。数据仅用于研究和模拟。候选已包含本机 Codex 研判入口及双策略市场模拟账本；真实执行数据源、长期质量与实际部署状态见 [任务清单](BACKLOG.md)。

## 安装与运行

在项目的 `prototype` 目录执行：

```sh
npm ci --ignore-scripts
npm test
npm run build
npm run start:production
```

默认使用独立 demo 库和生产静态文件，网页与 API 同源使用 4178 端口；不启动 Vite 开发服务器。原有 `npm start` 开发入口继续保留，使用 4178/4179 双端口。检查生产入口：

```sh
npm run health -- --production
```

空白研究模式：

```sh
npm run start:production -- research
```

原数据库切换前必须先备份并在副本验证；不要把演示库改名为研究库。运行器不自动载入 .env；环境变量沿用 SIGNAL_MODE、SIGNAL_DB_PATH、SIGNAL_FRONTEND_PORT 和 SIGNAL_API_PORT。生产模式只有网页端口监听；健康状态、版本与任务记录来自同一实例。

前台运行器会恢复意外退出的 API 子进程，最多 5 次并逐次退避；超限退出，避免故障重启风暴。它不能替代开机服务管理器。关闭浏览器不会停止任务；关闭终端或注销是否持续运行由系统服务管理器决定。

## 后台服务配置

生成配置不会安装、启用或修改系统设置。先确认路径、模式、数据库和端口，审阅具体候选后再启用。macOS 使用用户登录服务，Linux 使用用户 systemd；尚未完成 Windows 服务支持。

```sh
npm run service:config -- macos ./signal-hunter.plist demo
npm run service:config -- linux ./signal-hunter.service demo
```

命令拒绝覆盖已有配置。配置包含当前 Node、源码和数据库的绝对路径，属于本机生成物，勿纳入源码发布。长期目录应固定，移动后重新生成。macOS 配置不保证注销后或机器睡眠时继续运行；Linux 注销后的运行也依赖用户服务设置。

使用本机Codex的研究实例生成服务配置前，需要在该命令环境中显式提供`SIGNAL_CODEX_BIN`、`SIGNAL_CODEX_MODEL`及需要保留的`SIGNAL_CODEX_EFFORT`、`SIGNAL_CODEX_TIMEOUT_MS`。生成器将这四项配置写入私有服务文件，避免从前台切换到系统服务后丢失模型设置；不会复制其他进程环境或凭据。生成配置仍不安装、启用服务或模型任务。

macOS 在核对候选后，可使用 launchctl bootstrap gui/<用户数字ID> <配置绝对路径>；停止用 bootout 指定同一服务。Linux 在核对后把文件放入用户 systemd 配置目录，执行 daemon-reload 后启用。安装和真实主机重启验收是独立步骤。个人实例本轮实际启用与未验收边界见下节；生成配置不会自动启用其他实例。

## Mac切换与恢复的操作顺序

本轮个人4388实例已实际启用用户LaunchAgent，监督进程崩溃后由系统自动恢复；固定实例及Codex配置保留。源目录、Node、依赖和私有实例配置仍是运行依赖，整理分支或目录前必须检查服务指向。登录常驻不保证注销后或睡眠期间采集，真实主机重启/睡眠与连续运行仍需独立验收，实际状态只在[任务清单](BACKLOG.md)维护。

切换需要保留原服务文件和数据库，恢复只使用全新路径：

1. 核对服务label、用户ID、实例、数据库、端口、运行代码及恢复对象；原配置保存私有备份。只停止目标实例，不能按进程名称批量终止。
2. `bootout`后等待该label已从`launchctl print`消失，且目标端口已无监听，稳定检查后再替换和`bootstrap`。立即重新注册可能返回系统错误5；错误时优先恢复原配置并重新核对注销及端口释放，保留失败记录。
3. 完全停止写入器后为最新数据库创建一致备份，记录完整性、行指纹、计数与哈希。如果快照之后已有新业务记录，停止推进并重新备份；不能退回旧快照丢掉新增记录。
4. 将备份恢复到全新私有路径，保留恢复锁与全部任务暂停，核对固定实例及只读研究历史。切换服务配置后检查实际健康、数据库身份、业务记录和写入阻断；不因HTTP 200自动解除恢复锁。
5. 回退时停止测试目标并等待注销与端口释放，恢复原配置及原数据库路径，重新启动并逐项核对业务记录和原任务状态。原库、受锁恢复副本、两份服务配置、日志和快照全部保留。

本轮验证的是同版本程序的运营库/配置切换和返回原库。跨软件版本回退需兼容性核验及升级后新增记录处理方案；旧程序不得打开已升级库。真实主机重启/睡眠需另行安排窗口。

## 运行控制

主屏“查看状态”打开运行控制台。新闻、日线、分钟、本地备份分别显示暂停状态、开始/完成时间、最近成功、下次检查、错误及最近 50 次运行记录。

- 暂停：阻止后续运行，取消本进程中的采集请求；已提交的数据保留。
- 恢复：保留历史，重新安排该任务。恢复不批准交易。
- 重新检查：人工安排下一次执行；仍遵守来源冷却、暂停与数据库互斥。
- 自动研究政策开启后，新闻、自动研判、日线、分钟行情、观察检查及已启用的价格评估任务，连续全部失败达到3次仍按已保存时间后台重试；任务退避从30秒递增至最多15分钟，并取不短于原任务周期的间隔。来源403/429等独立冷却、模型额度、材料尝试上限、方案版本与数据有效性检查继续生效。部分源失败保留成功结果，其他来源和任务继续。
- 自动恢复不启用暂停任务；取消、恢复副本核对锁继续阻止执行。模拟执行、手工关联比较、备份、容量检查，以及未开启自动研究的任务，仍保留原失败待处理政策。启动自动研究只恢复新闻与研判，不自动开启价格评估或交易任务。
- 首页“后台进展”和“后台进度与记录”的下次时间包含后台自动重试，排除主动暂停、正在执行和需要手工处理的阻塞；日志保留全部失败与恢复结果。重试成功只证明本轮任务恢复，不表示行情已具备交易资格或研究已通过质量核验。
- 中断恢复：持久租约到期后恢复任务；旧执行者失去租约后不得再提交采集结果。

手动新闻、日线和分钟刷新也登记任务输入与结果。运行器每 10 秒检查到期任务；新闻默认 10 分钟、分钟默认 1 分钟检查，日线沿用交易日和缓存规则。检查频率不等于上游实时更新频率。

新闻、日线、分钟、备份以及研判、语义、观察、研究价格窗口、模拟执行和只读容量检查均已接入持久任务。旧候选模式不自动采纳；显式启动的自动模式按下文保存系统研判。执行依靠冻结批准和共享容量幂等，不能仅靠任务租约防止重复成交。

## 一致备份与恢复

运行实例每小时自动备份到当前数据库同级 `backups` 目录；第一轮启动也会检查是否到期。备份包含 SQLite 中的研究、材料、新闻、行情、账本、任务与控制状态，不包含环境凭据、操作系统服务配置或数据库之外的文件。每份备份附模式、表计数、完整性检查和 SHA-256。数据库备份采用 Node 的 SQLite 在线备份机制。

手动备份示例（仍在 prototype 目录）：

```sh
npm run backup -- create ../data/runtime/research.sqlite ../data/runtime/backups
npm run backup -- restore ../data/runtime/backups/snapshot-示例 ../data/runtime/restored.sqlite
```

恢复只允许全新路径；拒绝覆盖已有库、悬空符号链接，以及存在 WAL/SHM/journal 的目标。在私有临时目录复制、事务化暂停任务、标记运行中任务中断和待核对状态，逐表逐行验证后才以不覆盖方式生成目标文件。验证失败不会留下可被误启动的目标库。

用正确模式打开恢复副本。核对确认前，后台周期不重新筛选、更新事件、扩展关注或处理订单过期；模型中断记录不自动改写，HTTP 业务修改被拒绝。允许查看、暂停/取消和确认核对；数据库升级初始化仍可增加新表、规则记录等，需检查演练报告。核对研究、持仓与申请后点击“已核对恢复数据”，再分别恢复需要的任务。确认本身不会恢复任务。

备份不会自动删除；需定期检查磁盘容量。可按“备份保留与显式清理”节生成并人工确认清理计划。磁盘满只读模式及异地主机备份属于后续工作，不能把本机快照当作异地灾备。不要在运行中只拷贝 SQLite 主文件，遗漏 WAL 可能丢失记录。

## 诊断与降级

证券能力表分别展示日线与分钟来源、最新数据时间、接收时间和错误。日线获取成功不代表分钟可用，也不能证明具备可成交报价。当前执行能力始终标为研究观察。

- 上游 403：记录来源拒绝，保留缓存；不绕过权限或自动改用付费源。
- 来源超时：独立失败及有限重试；不能把失败显示成“没有新闻”。
- 服务存活与来源成功分开：健康接口只证明本机服务与数据库可读，不承诺上游正常。
- 任务“已完成”只表示一次执行结果，不能替代长期稳定性或识别准确率。

2026-10-01 对 A/H/US 各一个证券独立诊断：主源连接中断，备用源返回 HTTP 403。该抽查不能代表全部证券；本批未恢复分钟数据，也未尝试绕过拒绝。

## 有界真实行情核验

在prototype中运行：

```sh
mkdir -p ../session-artifacts
npm run market:verify -- ../session-artifacts/market-check-01 600519.SH 00700.HK AAPL.US
```

输出目录必须是全新路径且父目录已存在；已有目录会在请求前拒绝，最多12个指定证券。命令使用全新内存研究库，调用工作台相同的日线/分钟适配器、身份检查和来源冷却；不接受个人数据库路径，不触发后台调度或订单。403/429等冷却在本次运行内共享；命令没有自动重试，不应循环运行以绕过来源限流。

report.json保存来源请求结果、实际时点、缓存诊断、执行边界和账本不变；normalized-data.json保留规范化返回数据，其JSON紧凑序列化SHA-256写入报告。文件只在本地，需遵守供应商数据权限，不随源码发布。请求全部成功返回0，存在来源失败返回2，输入/保存错误返回1。退出0不证明实时、完整覆盖或可成交；检查具体数据状态和时区，美股未知主源时区仍不推断。

已知UTC及A/H适配器标明的UTC+8时间用于诊断。未明确时区、无效日期和未知市场日历继续显式展示；当前分钟末条可能不完整，盘中数据仍是研究参考。

分钟主源成功但时间无法核验时，会尝试已有Yahoo备用源的UTC时间；不把主源美股时间自行解释成北京时间或纽约时间。选择依据随新行情快照保留。备用源失败时保留主源的未知状态；若已有可比较时间缓存，未知结果只留档，不覆盖缓存。来源冷却仍生效，A/H已知时间的主源不新增请求。此选择并未证明延迟、全时段覆盖或可成交，也不因价格或内容差异而拼接两份来源数据。


## 本机 Codex 研判候选

当前模型入口使用已安装、已登录的 Codex CLI。调用会把当前事件的材料发送给 Codex 使用的模型服务，使用当前账号能力与额度；“本机入口”不是离线推理。不安装独立本地模型，也不读取或复制凭据。独立本地模型留待正式部署时评估。

在macOS/Linux调用入口，独立生命周期进程通过专用IPC持有本次CLI：应用进程退出或连接断开时，终止该调用的进程组；500ms后仍未退出则强制结束。同组残留子进程在CLI正常退出后也会收尾。不会扫描进程名或读取旧PID文件来终止其他程序；提示词、标准输出与生命周期消息分离。原超时、取消、诊断、调用计数与持久恢复规则保持。此机制不自动拉起应用，不取消远端已经处理的请求，也不保证生命周期进程本身被强制结束后的收尾。Windows沿用原直接子进程路径，尚无这项崩溃收尾保证；真实服务、其他系统和主机恢复仍需分别验证。

研究实例启动前明确配置下列环境变量（运行器不自动读取 `.env`）：

- `SIGNAL_CODEX_BIN`：已安装 Codex 可执行文件的绝对路径，不接受任意 shell 命令。
- `SIGNAL_CODEX_MODEL`：该账号可用且明确选定的 Codex 模型名称。本轮实测使用 `gpt-6-astra`。
- `SIGNAL_CODEX_EFFORT`：推理强度，默认 `high`；需与所选模型兼容。
- `SIGNAL_CODEX_TIMEOUT_MS`：单次研判超时，默认 420000（7分钟），最大 600000 毫秒。显式设置继续优先；定时后台研究不以三分钟交互等待作为默认截止。超时仍计入失败和调用次数，不保证远端退回用量。模型配置属于队列执行依据，旧任务保留原配置，不直接改写为新时限后继续。

配置后按已有方式启动独立研究实例。在“研究详情 → 材料与研究”点击“使用 Codex 生成候选”。生成前冻结研究版本、完整输入和指纹；运行记录保存在当前数据库的 `model_research_runs` 中。列表只显示最近 50 次，旧记录仍保留在数据库中。任务失败或取消保留记录，服务中断后的过期任务可手动重试，不自动重复调用。一个数据库同一时刻只允许一份模型研判。离线演示即使提供配置也不会调用模型。

材料包还包含已存材料标题和正文中的明确金额/百分数索引（source-quantity-literals/2）：绑定证据、材料版本、原文字段及UTF-16位置，保留原句上下文，明确币种和倍率使用十进制字符串换算。百分数10仍指10%，不改为0.1；含糊币种、冲突单位、可识别区间及括号符号不生成确定换算值。每包最多80项，记录提取总量与省略量；裸数字、科学计数及不支持的写法不作推断。它只帮助回看原文，不证明对应的财务指标、期间、预期或来源真实性，也不自动填入公司量级表。新索引纳入输入指纹，已有待采纳研判按原失效规则检查；旧材料和已存研判不重写。

服务端POST `/api/research/:id/model-runs`可接受`version,requestId`。请求标识为16–80位ASCII字母、数字或连字符；第一次提交冻结原输入，标识、版本、输入指纹和run在同一事务保存。未知响应以原标识和原版本重试，返回原运行的最新状态，不按当前材料重新调用；不同研究或版本复用标识拒收。失败、取消、中断后，原标识仍返回旧结果，新调用须用新标识。模型配置仍由本机服务管理，客户端不能指定模型、路径或推理配置。恢复核对前POST仍禁止；可先GET查看原运行。

新增`model_research_requests`表随完整SQLite备份保存，旧run不回填请求身份。只含version的旧调用继续兼容，不能据此获得请求去重保证。普通研判页面现在发送此请求标识，并按实例/研究身份保存会话中的原版本、请求和所选历史。未知结果以原标识重试；刷新/重开读取到同标识运行后无需再次调用。未确认的旧版本请求先核对原记录，显式丢弃后才生成新请求。列表范围外的已选ID继续按详情读取，旧运行不回填标识。会话选择不是数据库备份内容，关闭标签页可能丢失，服务端原运行继续保留。读取失败或采纳回执未匹配时，当前显示保留并暂停采纳，先刷新核对。

生成结果通过既有章节和引用校验后显示为“待复核候选”。本人点击“采纳为研判草稿”才保存研究新版本；旧版本保留，模型来源随手工编辑继续保留。采纳不等于完成核对，也不会创建、批准或执行订单。研究或材料已变化时拒绝采纳旧候选，须重新生成。结构和引用存在性校验不能证明结论正确，仍需复核事实、反证、量级与未知事项。

研究包含已填公司量级时，同一次五章研判须逐值返回结构化口径核对，不增加独立模型调用。每项绑定公司、量级记录及数值位置，分别标记模型判断口径一致、冲突、依据不足或人工假设，并说明主体、指标、期间及兑现性质。目标清单和版本进入输入指纹；漏项、重复、错误引用、原文不含所引片段，或“一致”引用中没有完整原文可支持的明确金额/百分数均拒收。不能从原区间截取单值绕过检查。其他业务单位可保留未知；该机制不自动读取财报、补齐市场预期或证明模型判断正确。

候选及已采纳草稿展示“量级口径核对 · 模型候选”，可展开原文引用。采纳后保留原输入版本与指纹；手工编辑五章正文仍保留这份历史模型结果，不将其改写为当前事实。不修改公司量级值、字面匹配记录或交易状态。旧候选原始记录保持可读，当前输入指纹改变后不可直接采纳；旧研判不补造逐值核对结果。输入/输出大小和超时限制仍适用，超限或失败不会静默省略目标。

调用使用独立临时目录、只读沙箱、临时会话和明确模型配置，不继承桌面任务的工具管道或自定义模型配置。shell、插件、应用、浏览器、网络搜索等相关工具选项关闭，并在运行事件中发现工具活动时终止并拒收候选。当前实测 CLI 仍会声明部分工具，并产生 code-mode host 关闭的运行警告；不能据此宣称运行时完全没有工具。临时运行文件会清理，原始提示词可由输入、提示词版本及代码恢复，候选保留原始模型 JSON、模型/CLI/提示词/Schema 版本指纹及用量；原始 CLI 日志不进入页面。

输入超过 512 KB 时明确拒绝，不静默截断。默认三分钟超时不保证所有材料都能完成；真实合成样本耗时约 145 秒。大材料分层处理、更多真实样本质量与长期运行仍需验收。

如需离线整理材料后单独调用，也可使用已导出的标准研判材料包：

```sh
cd prototype
npm run research:codex -- /path/to/packet.json /path/to/new-output-directory
```

须先配置上述环境变量。输出目录必须不存在，父目录必须存在；命令保留 `input.json` 及 `candidate.json` 或 `failure.json`，只写本次全新目录，不打开研究数据库。此命令的候选不会自动导入页面；页面内发起的候选才进入上述采纳流程。材料、生成结果与数据库都属于本地研究资产，不进入 Git 或公开发行包。

## 固定已有研究入口

默认数据库路径相对于当前源码副本。换 checkout 或工作树后运行 `npm start`，会打开该副本的演示库；它不会自动找到原研究库。已有研究应只读登记一个固定入口，放在源码目录之外：

```sh
npm run instance:create -- /absolute/data/research.sqlite /absolute/config/research.instance.json '我的研究' 4178 4179
npm run build
npm run start:instance -- /absolute/config/research.instance.json
```

登记要求已存在、已标记模式且有历史版本的数据库；不会初始化、迁移或覆盖数据库/配置。配置以绝对路径绑定数据库、模式、端口和最早研究历史的 SHA-256；无研究时采用初始账本历史。启动时在 schema 初始化之前，只读验证模式与该历史版本。文件丢失、锚定历史缺失或指纹不符时停止，禁止默默新建空库。后续合法新版本保留旧历史，因此不改变身份。该核对用于识别数据集，不是完整性校验或迁移验收；从同一历史复制出的库仍需人工核对路径与用途。

配置可跨源码工作树复用；生产静态入口固定使用配置端口。环境变量 `SIGNAL_INSTANCE_PROFILE` 也可指定同一绝对配置路径；与模式、数据路径、端口或静态入口冲突的环境设置会报错。配置文件含本机路径，权限为0600，`*.instance.json` 被 Git 忽略，不在发布允许清单内。不要手改配置来绕过历史核对。切换候选代码仍须先备份、在副本验证兼容性，并完成具体版本的部署审阅；固定入口本身不会批准升级。

页面顶端显示数据集名称、模式、主题数、文件名和身份短码。未登记的入口明确标为“入口尚未固定”。固定实例提供的身份以配置为准；未固定入口只按数据库路径区分，不能识别同路径文件被替换。API 的 `/api/health` 与 `/api/data` 提供身份，但不暴露绝对路径。浏览器绑定首次读取的数据集，编辑请求携带 `X-Signal-Instance`；若同一端口换库，旧页面的请求被拒绝，需要刷新并核对数据后继续。脚本调用变更接口也必须先读健康状态，再携带其 `instance.id`。

生成系统服务模板时可设置 `SIGNAL_INSTANCE_PROFILE`，模板会保留固定入口并采用独立服务名；仍只生成，不自动安装。配置和系统服务文件需要另行备份，SQLite 快照不包含它们。私人数据继续保存在 SQLite：新闻修订、研究历史、材料及模拟记录与代码 Git/PR 分离；代码切换不意味着数据应被删除或重新采集。

## 自定义观察条件与待办

“观察待办 → 设置观察条件”按研究保存观察配置。可组合1–8项规则，选择“全部满足”或“任一满足”：指定复核时间（录入为北京时间）、研究出现新版本、新增/修订反向线索、关联证券的日线或分钟柱收盘价格达到本人填写的原币阈值。研究和反证基线在保存/恢复/重新监测时冻结；暂停、修改与恢复产生配置新版本，旧定义和命中记录保留。最多保存500项配置，达到上限需复用现有配置。

后台每10秒尝试检查，受已有任务暂停/租约控制；页面读取不执行检查。每个配置版本最多生成一条待办，完成回执不会自动重新触发。需要再次观察时明确选择“重新监测（新版本）”；修改、恢复也重新监测。单次满足记录冻结当时的配置、研究版本、比较值、行情来源/时点/接收时间/指纹、日历版本及受影响持仓。最新检查可以显示条件后来不再满足，历史命中仍保留。待办及检查状态在同一事务保存，失败后不会丢失应有的提醒。

价格是研究缓存，不能用于交易执行。在线模式要求最近来源请求成功、证券币种一致、接收时间有效，日线日期对齐或分钟处于现有诊断允许的近期/休市缓存状态；未知时区、过期、异常时间、缺失价格或移除的公司显示“无法判断”。不补零、不猜测两次采样之间的穿越，也不把延迟未核验写成实时报价。演示价格始终标为合成。AND中任一未满足使整体未满足；否则有未知则未知。OR中已知满足可命中，但其他未知项仍逐项显示，不作为满足依据。

该流程只生成站内复核待办，不修改研究内容、组合参数或订单。后续候选增加下述采样穿越/持续时长；自然语言条件、价格异常统计和站外渠道尚未实现。未提交配置草稿按实例/研究/配置隔离保存于当前浏览器会话；刷新后可继续，浏览器存储失败时提示限制。研究或配置并发变化必须显式核对，不能静默覆盖新版本。

### 分钟采样穿越与持续时长

价格条件新增“触发方式”，默认仍为原有“当前值达到阈值”。另外两种方式自动选择分钟数据：

- 相邻有效采样穿越：向上要求前一有效价格严格小于阈值、本次大于等于；向下反之。第一个样本只建立基线，初次即高于阈值不会冒充向上穿越。
- 有效采样持续满足：本人填写60–21600秒时长；满足阈值的多个新样本，其来源时间跨度和首次至当前实际观察跨度均须达到该时长。晚到的缓存不能把首次观察之前的时间计入。任一不满足样本清空持续窗口。

两种方式都需填写60–600秒的最大采样间隔；相邻新样本的来源时间间隔和实际观察时间间隔都不得超过该值。轮询旧缓存不刷新新样本的观察时间。表单初始显示180秒，保存前可调整；它是允许的采样缺口，不是延迟承诺。来源失败/缺失、过期、币种或时间不一致、同一时点价格修订、来源/时区变化、间隔过长、时钟倒退及跨交易日/午休都会重建基线。数据时点必须不早于本配置版本的启用时间；来源日期水位防止较旧行情倒退后形成假穿越。同一时点重复返回不推进时长、不再次形成穿越；持续窗口最多512个样本，超过上限重新开始，不截断后继续宣称完整。

持续指已观察的离散样本，不证明缺口中的价格始终满足，也不是逐笔行情。时序方式在休市或日历未覆盖时不判断，普通“当前值达到阈值”仍沿用既有休市缓存逻辑。AND/OR只计算当前检查轮；穿越事件不会锁存到其他条件未来满足时。每版已生成的待办保持原始命中依据，即使最新检查显示重复/中断也不覆盖它；重新监测须明确建立新版本。

窗口保存在现有观察检查表中，事务与待办一起提交。采样算法 sampled-price/2 按新样本的实际观察间隔判断连续性；升级时旧算法的未完成窗口重新建立基线，已生成待办、命中依据和回执不重写。重启可延续未超过间隔的窗口；停机过久仍重建基线。命中详情展示源时间、实际接收与观察时间、价格、来源和逐样本指纹；日历与采样算法版本随完整窗口保存。此功能未接通实盘，不改变双池风险或自动批准卖出；当前时序日历继续使用项目既有研究日历，不能当作交易所执行规则认证。


## 升级前恢复演练

独立发行候选应先用 `release:prepare` 导出到全新目录，再按锁文件安装依赖、测试和构建。不能通过链接开发目录的 `node_modules` 证明新用户可以安装。当前本机已验证缓存离线独立安装；首次联网获取、干净系统与其他平台仍是不同的验证范围，实际记录见[任务清单](BACKLOG.md)。导出包不带数据库、依赖目录、构建输出或私人恢复记录。

恢复演练器默认不启用文件系统备份与容量功能；首次使用生产入口打开同一受锁副本时，可以新增空容量记录表及暂停的备份 / 容量任务。应分别核对这些明确初始化增加项、全部旧业务行保留和随后暂停周期的整库不变，不能仅凭表总数不同判失败，也不能只核对总数而忽略旧行变更。核对恢复只解除待核标记，任务仍须按既有运行范围分别恢复；测试只能在独立副本进行。

先对当前实例做一致备份，再用候选代码演练。仍在 `prototype` 中执行：

```sh
npm run backup -- create ../data/runtime/research.sqlite ../data/runtime/backups
npm run recovery:rehearse -- ../data/runtime/backups/snapshot-示例 ../session-artifacts/recovery
```

第二条命令只接受已有备份目录，不接收运行库路径。每次生成新的 `rehearsal-*` 私有目录，内含 `candidate.sqlite`、`rollback.sqlite` 和 `report.json`，不启动监听端口、不启用任务、不配置模型，不确认恢复。报告包含候选服务代码/共享规则/运行脚本/依赖锁的逐文件 SHA-256 及总指纹；Git HEAD 仅作参考，未提交代码以内容指纹为准。

验证包括完整性/外键检查、全部应用表的类型化逐行哈希（保留重复行、BLOB、64 位整数）、模式与结构、候选初始化后的旧行保留、读取与后台暂停周期无写入，以及从原快照独立恢复回退副本。只有任务暂停、租约清除、运行中任务中断和恢复核对标记是恢复时允许的内容变化；其他触发器或意外写入会使恢复失败。候选初始化允许增加表和记录，但逐项报告，不把它当作迁移批准。已有表结构改变或旧行缺失/替换会使演练不通过；合法的数据迁移也需另行编写并审阅明确的预期转换。命令通过返回 0，失败返回 1；失败报告和隔离副本留给诊断。

回退副本保持升级前数据，并不证明旧程序已启动或所有业务兼容；不得直接让旧程序打开已升级库。切换后若有新增研究/交易记录，它们只在升级后的库中，退回旧快照不会自动合并新增记录。保留两边库及代码候选、固定实例配置和服务配置，再设计具体切换/回退步骤。数据库快照不包含外部配置、凭据和其他文件。

该命令目前全量读取并排序行指纹，适合本机当前数据量；数据显著增大时需要另行测量耗时、内存和空间。文件损坏检查不证明硬件可靠性，也不替代异地备份、服务常驻或长期运行验收。

## 公司量级、敞口与预期差

点击关联公司 → 完善公司分析 → 量级、敞口与预期差 → 添加量级记录。每家公司最多8项，各项独立填写指标、主体及业务口径、比较期间、共同单位和依据。所有输入须明确确认同口径；系统不做币种换算、单季年化、订单额转收入或收入转利润。比较基准、涉及规模、原预期、新结果可以留空；填写后分别选择“材料数值”或“人工假设”，材料数值必须引用本研究已有证据。引用选项标出材料或新闻版本，避免同名修订混淆。

金额提取保留原文字节内容及字符位置，支持普通空格、制表符和不换行/窄空格等Unicode横向间隔；HTML的 `&nbsp;` 不再导致“百万/十亿”倍率丢失。空格分组数字、跨行拆开的单位及不支持的缩写保留为未识别，避免截出较小金额。索引版本升级后新材料包指纹改变，旧待采纳候选须重新生成；旧材料、已存字面检查和研判不会自动回填。

保存量级时，系统逐值检查所引不可变材料快照的完整性，并将明确币种与倍率换算后匹配原文金额/百分数。例如百万USD、USD million及百万美元可对应同一金额；含糊的美元符号、无明确币种的万元、台数、科学计数写法或复合单位暂不匹配。公司详情分别显示全部引用匹配、部分匹配、未找到、无可核对材料或不支持的单位/数值；“未找到”不证明原文不存在，正文提取范围和数字写法仍可能造成遗漏。每个引用最多保存3处匹配片段，同时记录总匹配数、原文字段/位置、材料版本及指纹。匹配扫描完整已存标题/正文，不受研判包80项索引上限影响；不重新联网读源。

找到同币种同值只证明字面对应，不证明数字属于所填主体、指标、期间或事前预期；订单、约数、区间、否定及条件仍须核实。匹配结果随研究版本冻结，后续材料修订和页面刷新不改旧记录；仅显式重存量级才按选定引用重新检查。历史无检查记录的比较明确标示未做匹配，单纯修订公司关系且未提交量级时保留原结果。未匹配不阻止保存研究，也不改变原有人工输入计算或交易权限。

- 变化差额＝新结果－比较基准；相对变化＝差额÷基准绝对值。零基准仅给差额，缺失输入不填零。负基准按绝对值计算，亏损收窄不标作收入增长。

- 原预期和事件/结果时点可留空；填写时使用带时区的ISO时刻，例如 `2026-10-01T09:00:00+08:00`。仅当原预期选择材料数值、全部所引材料已在填写的预期时刻前获取，且该时刻早于事件时点，才标明材料事前已可用。即使满足，也不证明数值解读正确、市场共识、价格尚未反映或独立前向验证。

## 双策略持仓巡检

已初始化的激进/稳健模拟池现在与场景持仓一起由 `observations` 后台任务检查；仍可在运行控制中暂停，恢复副本核对前不运行。检查只读取服务器配置的执行输入，不请求或接受网页提交的价格；免费研究收盘缓存不能作为执行输入替代。

巡检按账户与持仓批次分别形成站内待办，覆盖研究版本变化、开仓基线之外的反证、研究归档/缺失、持有复核截止、既有亏损/跟踪回撤退出线、池回撤、发行人跨市场集中度、同一研究主题集中度、可用现金与估值缺失。主题集中度以当前研究ID分组，不宣称自动识别跨研究同一产业主题。发行人身份不一致、价格/FX失效或净值未知时，相应比例无法判断；缺失输入本身形成复核任务。集中度使用当前持仓，现金底线使用扣除已批准买单剩余预算后的现金；申请时的预计仓位检查仍由原订单风控承担。

同一条件持续命中不因价格小幅变化重复通知。有效输入明确恢复后再命中，产生新的触发轮次；未知不等于恢复。研究版本、证据内容、风险配置、严重程度或持仓批次变化可产生新待办。平仓后当前检查退出，历史待办与回执继续保留，不能用新建同证券持仓继承旧回执。

`market_observation_states` 保存每项条件当前状态和轮次，`market_observation_peaks` 保存实际观察到的高点及形成高点的报价/估值快照；与待办在同一事务中提交，失败回滚，不消耗触发轮次。审批指纹绑定使用的高点，变化后旧审批输入必须重新核对。高点用于既有订单风控，但观察任务不推进订单、结算、成交或账本版本。只有检查时有效的输入才能提升高点，不推断间隔中的盘中最高价；停机、来源失败期间不会补出未观察价格。重启保留高点与状态，检查时钟倒退拒绝该轮。

“观察与持仓待办”分别展示当前命中/未知数量和历史待办，可展开首次命中时的账户、账本/配置版本、持仓批次、风险指标、来源和报价时间。已读/完成/重开沿用版本化回执；完成不平仓、不解除买入限制。原研究/交易版本、高点和历史输入不因回执改变。

这些是模拟研究复核。真实执行适配器、跨主题语义识别、统计异常、站外通知及长期有效性仍待完成；当前公开实例没有可执行行情，不以合成测试声称接通市场或实现交易收益。

## 模拟持仓自动退出候选

已初始化模拟池沿用其既有止损、跟踪回撤和持有复核期限，自动将命中的持仓批次整理为只读候选。首页原“买卖待决定”仅计可批准且本人尚未选择暂不退出的候选；点击进入原组合页并展开对应方案。查看、展开和刷新不创建订单，不启动任何任务，不改变风险参数。

同一研究 / 同一证券的触发批次合在一份候选内，仅取其中已到可卖时间的整数申报单位；未触发的其他批次不进入。限价按当前bid扣除本池配置的不利滑点，再向下取整至有效报价单位。期限取“报价时点加本池最长订单分钟数”与当前交易时段收盘的较早者；这是条件申报价格和有效期，不是最优卖点、目标价或保证成交日期。费用及净款按候选限价、当前FX估算，部分成交与后续费用可能不同。碎股 / 尚不可卖余量保留跟踪。

来源、身份、币种、时点、FX、费用、交易时段、单位和容量继续走原市场模拟风控。当前研究不等于建仓版本、证券移除、已有同研究证券的未结束卖单、休市或输入未知时不能快捷批准，原风险仍保留。只有本人点击“批准此模拟退出”才在同一事务生成已批准订单与决定记录；准确候选指纹、持仓 / 研究 / 配置 / 行情依据、请求标识一起保存。提交时重新计算，输入变化拒收旧决定，不偷偷改数量或价格；失败回滚，重试不重复创建。

批准后的订单仍沿用原执行任务，必须等到批准之后的新报价，接受限价、容量、部分成交、费用、到期与配置 / 研究失效约束；只从冻结的目标批次分配成本。其余持仓不代卖，不做空。选择“暂不退出”留档且不会解除风险；同持仓数量、触发种类与研究 / 配置组合不会因新报价再次计入首页新待决定，仍可在原账户查看并重新选择批准。清除后同组合再触发的观察待办沿用原轮次机制，此候选的暂不退出选择不会自动撤销；新的批次、数量或触发种类另行呈现。

这条路径仅补齐既有模拟规则的退出准备与最终决定，不自动解释自然语言条件、不形成新买入方案、不替实际账户设定阈值，也没有接通真实供应商。账户操作后重新读取首页概览，原持仓账户、事件与展开保持；当前合格的十进制文本报价可正常显示，缺失 / 不合格估值仍未知。决定及完整冻结依据在原账本历史查看，无新增状态表。

## 已保存材料的事件比较

从“事件追踪 → Codex 语义比较”分别选择左、右侧新闻或材料。材料列表搜索标题、来源或URL，每页20份，只提供同文档最新保存修订；正文通过研究的既有材料入口添加。网页提取文本沿用原来源读取记录，人工材料与摘录明确区分，选择材料不会重新请求来源。

生成比较时校验内容指纹并冻结完整正文、来源、阅读范围、时间、材料修订与模型记录。标题/标题沿用event-pair-1；含材料的比较使用event-pair-material-1，输出quoteField指定title或body并逐字校验。超过512KiB的材料包明确拒绝，不发送截断输入。详情可展开冻结正文与内容指纹，比较列表不传正文。

同文档出现新修订后，旧候选和人工决定仍保留，当前采纳状态失效，不允许继续采纳旧候选；新比较沿用同一文档对的决定序列。原新闻标题模式的历史输入、候选和决定不重写。采纳仍仅保存本人关系判断，不自动归并证据、研究、证券或订单。正文内容、来源身份与模型推论仍需核验，少量合成调用不证明识别质量。

## 比较判断与跨研究召回

在“研究详情 → 关联事件”查看“已采纳比较中的研究线索”。仅检索当前有效的人工采纳结果，按新闻ID及修订或材料ID及修订匹配两侧研究证据。扫描相关已采纳记录，不限比较界面的最近50次；每页20条，显示总数。未采纳、已撤销、过期、无法判断或缺乏关联的比较不会形成有效召回；未保存在另一研究中的输入也不会凭标题推断关联。归档研究保留标签。

选择“用此比较核对”后仍需本人选择研究关系并填写说明。服务重新核对两份研究版本、比较决定版本和证据绑定，冻结比较编号、输入/输出与依据指纹、模型、引用、采纳说明和左右方向到研究新版本。原方向始终是比较左侧相对于右侧，从右侧打开不自动解释为后续进展；“相关线索”初值可修改，不是自动认定同一事件。

比较决定或证据后来变化时，旧研究关系与历史不重写，页面显示“依据需复核”，导出的研判包也带当前依据状态。由原有效依据生成、尚未采纳的模型草稿将因输入指纹变化被拒绝采纳。关系保存和草稿采纳均在数据库写锁内再次核对，防止另一实例先撤销或修改目标后旧页面继续提交。本人仍可另行撤销研究关系，冻结依据留在历史中。

这是已核对比较的直接召回，不是全库自动模型筛选、实体身份确认或传递聚类。A与B、B与C有关系不会自动推断A与C，同一来源被多份研究引用也不能增加独立佐证数量。

## 日线来源缺口与倒退

“查看状态”中的证券行情来源诊断显示应有收盘日，并区分“来源尚无该日日线”和“该日收盘价缺失”。收到日期行和成交量，但收盘价为空时，仍按缺失处理；最新盘中价不能补成收盘价。公开来源可以HTTP成功但日线仍然落后。

若新响应最后有效日期比活动缓存更早，服务将可解析的规范化响应追加到 `daily_snapshots`，保留 `daily_quotes` 的旧值和原接收时间，记录 `daily-regression`。来源失败期间价格观察不把保留缓存当作健康输入。后续有效同日修订或更新交易日可以恢复；按既有来源冷却与重试规则检查，不因为保留缓存尚新而额外等待六小时。

历史快照是规范化结果及内容指纹，不是每次HTTP原始字节归档。新返回和旧缓存不会拼接成来源未实际提供的曲线。此保护仅防最后有效收盘日倒退，不能证明旧价格正确，也不能验证复权、公司行动完整性或可成交性。

## 日线统计观察

“设置观察条件”新增“日线统计异常”，可与现有时间、研究更新、反证及价格条件按AND/OR组合。选择本研究的关联证券、日涨跌幅或日成交量、5–120个历史样本、1–20倍标准差及高于/低于/双向偏离。表单初值20个样本、3倍、双向只是可修改的研究设置，保存后才启用，不是经过验证的策略参数。

日涨跌幅为相邻完整交易日收盘价比值减1，再乘100。N个基线涨跌幅需要N+1个历史收盘价，加上最新被检验日，共N+2根日线；成交量需要N+1根日线。基线只取最新样本之前的N个值，计算均值和以n−1为分母的样本标准差，偏离z=(最新值−基线均值)/标准差。高/低比较相对基线的正负偏离，不等于绝对上涨/下跌；不假设正态分布，也不输出显著性或未来概率。

全部窗口日期必须与项目研究日历中的连续交易日对齐，且最新日线在获取时和检查时都已经结束。缺少样本、停牌造成缺口、重复/乱序/非交易日、空收盘价、窗口内已报告拆股/分红等公司行动、未记录口径、来源失败或缓存落后时不计算命中。波动为零或小到无法稳定标准化时显示无法判断，不产生无限分数。供应商报告的成交量0可保留；缺失、负值、非整数或超出安全整数范围保留为空，不能补零。旧日线缺成交量时需刷新，原快照不修改。

新增日线保存成交量口径、供应商重复日期记录和 actionsParsed 解析标记。公司行动分组或日期格式无效时，本次日线解析失败，不能把丢弃坏记录后的空列表当作没有行动。daily-anomaly/2 要求明确的解析标记；旧缓存需刷新后才能产生新的统计判断，旧快照与命中记录不补写或重算。标记只证明本次返回的格式通过解析，不证明供应商覆盖完整；原价格读取与图表保持兼容。价格复权、成交量单位、公司行动完整性和源延迟仍未独立核验，排除已报告行动不等于确认没有其他行动。日线成交量不能代表排队后可成交数量。只使用现有日线来源，不把统计计算当作接通实时执行行情。

配置保存后可以立即检查当前最新完整缓存，不只等待保存后的新日线。每配置版本至多生成一次待办；重新监测产生新版本，可再次检查同一日期。命中详情冻结原始窗口、实际接收时间、基线范围/样本数、均值、标准差、偏离程度、数据指纹及算法/日历版本。缓存后来修订、来源暂时失败或完成回执都不会重算旧命中。统计只形成研究复核，不修改研究、风险阈值、账本或订单。

## 自动模拟执行

“查看状态”新增“自动模拟执行”，首次启动默认暂停；“恢复”表示启用，随后约每10秒检查两个已初始化的模拟池。启停与任务记录保存到SQLite，正常重启保留；恢复副本仍需核对且所有任务保持暂停。此任务只用于市场模拟，没有真实下单接口，不会初始化账户、替本人批准订单或自动批准退出申请。

执行沿用既有审批、报价时间、队列/数量、FX、风险、可卖与结算检查；已批准订单可以等待、部分成交、完成或过期，未批准订单不会成交。没有合格输入时保留未成交和原因。已记录的卖出款可按其冻结结算时间入账，不依赖重新取得行情。任务“已完成”表示完成检查，不代表有成交、来源可用或策略有效。

两个账户按最早尚未完成的批准时间依次检查，同时间按账户ID排序；每个账户内部仍按现有订单顺序，不承诺逐笔市场撮合公平性。各池独立事务，一个池失败后继续检查另一池；同一报价的可用数量仍共享消耗。全轮失败沿用有限重试，部分失败会在后续周期继续检查，可由本人暂停。任务token写入产生变更的账本事件，便于对应任务记录；没有变更时不额外创建账本版本。

暂停只停止自动推进，市场模拟窗口中的“检查订单、成交与结算”仍可由本人执行。窗口随工作台约15秒刷新最新账户与历史；执行中不覆盖编辑草稿，账本版本变化后清除旧审批核对结果，仍由服务端校验精确版本。该候选尚未接入正式执行行情适配器，本地演示和测试使用合成输入，不能声称已验证真实成交。

## 持久比较批次

从“事件追踪 → Codex 语义比较 → 持久比较批次”加入2至10份新闻或已保存材料，预览所选全部配对；n份输入对应n×(n−1)/2次初始调用，最多45次。确认建立后保存到当前数据库。先前预览后若输入修订，建立会被拒绝，需重新选择当前版本。不会自动提取新正文、搜索全库或持续扫描新新闻。

首次“批次调度”默认暂停；恢复后继续所有未单独暂停的已建批次，每10秒至多发起一项，和单次比较、五章研判共用模型名额。各批次可单独暂停/继续/取消未开始项目。暂停或取消队列不会中止已开始的模型调用，结果仍保存；需要中止时打开该项结果单独取消。运行控制台也能控制批次调度。

输入全文与配对保存在`semantic_batches`，队列和历次调用ID在`semantic_batch_items`，操作记录在`semantic_batch_audit`；具体输入、输出与人工决定沿用`semantic_runs`和`semantic_decisions`。这些表随既有SQLite一致备份一同保存，不进入Git。页面显示最近50个批次，更早记录仍在数据库中。

重启保留队列与启停状态；过期中断的已发起调用不自动重跑。失败、中断或单项取消可明确重试，每次增加一次调用，旧输入和结果保留。整批已取消时不能重试。排队输入、模型配置或提示词发生变化后，对应项标记失效且不调用，需重新建立批次。调度存储故障沿用有限重试和异常停止；这种重试不重复已提交的模型调用。恢复副本完成核对前禁止推进。

本机Codex入口仍使用账号额度；本批没有另装离线模型。全部候选仍需人工核对和采纳，批次结束只表示队列已处理，不代表判断正确、研究已合并或交易已批准。

## 事件身份与聚类

进入“持久比较批次”，选择批次后点击“核对事件簇”。同一信息重复、同一事件进展和反向变化可提出候选范围；页面列出组内所有配对。只有全部组内比较一致、输入仍为当前版本、没有撤销或另一比较决定替代时，才可填写名称与核对说明并确认。未逐条人工采纳的模型结果仍是候选；确认事件簇是另一次明确的人工作业，不自动登记成对采纳或研究关系。

A—B和B—C判断相同而A—C不一致时，整组列为冲突，不依赖传递关系归并。相关、类比、未知或未完成配对单列；单项材料显示暂未归组。范围仅限选定批次2至10份输入，不是全库聚类，不保证一篇材料内的多个事件已经拆开，也不保证模型引用支持其结论。

确认后生成稳定ID；保存名称、说明、成员身份/修订、比较引用、模型来源、人工成对决定版本、批次指纹和算法版本。`event_clusters`保存当前版本，`event_cluster_versions`保存不可变历史，`event_cluster_members`保存当前分配，`event_cluster_commands`保存幂等回执。原始正文及模型输出仍保存在既有材料/批次/比较表。全部随SQLite备份，工程Git不代替数据版本管理。

更新或扩充时，将原簇全部成员的当前版本加入新比较批次；核对页面识别已有簇并保存新版本，稳定ID不变。缺少原成员时拒绝部分替换。成员同时命中多个活动簇时不能直接合并；需先审阅各簇并明确归档错误归组，再重新确认。归档释放当前分配，旧成员、引用和决定仍可从“事件簇记录”的归档筛选查看。

输入修订、比较撤销/不采纳或决定版本变化，会使旧簇显示依据需复核，旧版本不会被自动修补。保存前在同一写事务内重算预览与成员分配；并发变化、旧版本或旧预览会拒绝，页面保留已输入说明。刷新改变预览后需明确载入当前预览才可再保存。恢复副本核对完成前禁止确认与归档。

“研究详情 → 关联事件”显示当前证据所属事件簇，区分簇依据失效与研究仍引用旧版材料。这个入口只是读取分配，不修改研究证据、主张或账本，也不将簇直接写入独立评估标签。自动发现、实体消歧、跨批次拆分/合并工作流、质量样本及前向独立性仍需继续完成。


### 语义比较的事件时间依据

新生成的标题、正文及混合比较分别保存时间依据。原文明确日期保留源文本的日期或期间片段，不自动翻译、补年或变成标准时间戳；相对词（如“今天”）保留原词及上下文，来源发布日期在旁单列，具体日历日期仍待核对。没有支持的本侧时间证据时填未知。当前支持英语today/yesterday/tomorrow和中文今天/今日/昨天/昨日/明天/明日/本日/当日；其他相对表达暂记未知，不推测换算。

服务端拒绝缺少时间依据的新结果、跨侧/跨字段引用、原文中不存在的日期、将相对词标成确定日期以及带日期的未知项。引用必须真实存在，但不能自动证明上下文语义、事件发生或法律生效时间，仍需本人核对。

旧结果显示“旧版未记录时间依据”，原材料、输入、输出与决定均保留；旧结果不会被后台改写为新口径。新提示词标识追加`event-time-evidence-2`，输出schema另有指纹；未执行的旧批次会因执行指纹变化而失效，须重新预览后明确建立新批次。此升级不主动补齐历史来源发布日期，也不迁移个人研究库。

### 网页发布日期与材料修订

“研究详情 → 材料与研究”中，重新读取公开网页使用`public-article-7`。读取文章发布时间元数据、当前页面的Article/NewsArticle等JSON-LD字段，以及`datePublished`、`pubdate`和常见明确发布日期标记。不采用修改时间、任意正文日期或其他文章的结构化日期；网页提取完整性仍需核对。

仅日期保存为YYYY-MM-DD；ISO时刻须带明确时区，保留原偏移。支持完整英文月份和中文年月日。机器时区不参与推测；缺时区、不支持格式、字段不一致或数量/长度超限均显示未知。最多20个候选、每字段200字符；超限标记会保留，但过长原值不保存在该字段中。当前策略较保守：即使两个字段给出一致的带时区时刻，第三个缺时区字段也会使结果未知；可展开“日期读取依据”逐项核对。未知不丢弃已成功提取的正文。

原字段、读取状态和规则版本随材料指纹保存，依据变化也会产生新材料版本；相同内容与依据重复读取保持去重。旧版不补写字段、不更改日期；依赖旧修订的比较提示失效，原输入、输出、决定和研究历史仍保留。读取器不会自动批量重读个人材料，页面来源字段也不充当事件日期或历史可交易性证明。

2026-10-03真实读取的两份NVIDIA历史公告补出了2020-09-13和2022-02-07，均仅日精度；微软Nuance完成公告同时包含带时区08:00与无时区00:00字段，新版本保留未知，旧版本08:00 UTC仍可查看。结果与限制记录在[本轮读取验收](evaluations/publication-date-20261003.json)。这只是3篇英文历史页面的定点验证；中文、其他站点与全部日期格式仍需扩展验证，不表示所有来源日期已完整。

### 英文公司公告的日期规则

`publication-date-3`在Adobe新闻文章和Amgen新闻稿的精确HTTPS主机/路径上增加日期规则。Adobe读取唯一文章标题紧邻日期行，并核对标题一致的CardDate元数据；日期行含没有时区的时钟值，因此仅保留明确日历日，不生成UTC时刻。Amgen只读取匹配新闻稿容器中、地点后且紧邻PRNewswire分隔符的日期行，支持该位置的英文月份缩写；不会把正文背景日期或其他页面的同名元素当发布时间。保留原始日期文字，候选冲突、非法日期及既有长度/数量超限继续返回未知。

日期规则与正文范围规则分开版本化：旧`publication-date-1/2`和`article-extraction-1`仍按原规则验证，不因新URL规则失效或被重新解释；重新读取会新增材料修订。微软带时区/无时区元数据冲突仍保留未知，事件时间也不会自动用发布日期替换。三篇真实网页的原始HTML诊断与应用网络读取已在本机验证；这不表示全部公司网站或全文/附件覆盖。

### 中文官方页面的日期规则

证监会的官方文章路径和金管局的繁/简中文新闻稿路径增加有界读取规则。证监会只采用文章信息栏明确标注的日期；发现PubDate与同页“页面生成时间”完全匹配时，保留两者原值和排除原因，避免把重建页面的日期当成文章日期。没有匹配标记时不静默排除，原有未知/冲突规则继续生效。规则绑定精确官方主机和文章路径，其他网页的同名CSS元素不会自动套用。

金管局只读取新闻稿标题旁的日期；不使用页尾修订日期，也不依据通用date元数据里的午夜值推断精确发布时间。已验证范围是繁/简中文页面，英文缩写日期未因此扩展。候选日期和排除字段共用20项上限，原值和排除上下文分别有200字符上限；超限结果未知。

新版`publication-date-2`增加页面规则标识与排除字段，来源URL、依据和材料指纹一起校验。旧`publication-date-1`不会重新解释或补字段；重新读取产生新材料修订，旧结果保留。四篇历史中文页面的[验收元数据](evaluations/chinese-source-20261003.json)公开记录来源、日期及指纹，正文和诊断HTML只在本地私有档案保存。普通材料读取器仍不自动存整页HTML。

逐段核对只说明所选文章容器的31个非空段落出现在提取文本中，忽略了空白差异；不证明链接、附件、表格或语义完整。PR #35验收时证监会提取文本仍夹带字号控件文字；当时未修改正文提取算法、拆解多事件、调用模型或验证政策实际适用性。后续正文范围改动见下节。

### 正文范围与附件未读提示

`public-article-4`增加`article-extraction-1`记录。证监会指定文章页仅移除已核对位置的字号/分享控件，其他网站不按相同类名清理。证监会及金管局匹配的单一正文容器先扫描链接；布局不匹配和其他网站扫描Readability提取HTML中的链接。页面整体、脚本动态附件及其他未识别入口不在完整性保证范围内。

材料详情和冻结语义比较显示附件入口及未读状态。格式只是URL或名称提示，没有下载或验证文件类型。最多记录30个不同HTTPS地址，名称最多200字符、地址最多2000字符；超限和地址不符合展示规则另行提示。空列表、旧材料无字段、移除控件或未截断，都不表示全文/附件完整读取。

提取范围纳入材料指纹；重新读取生成新修订，旧内容、旧模型结果与人工决定保持原样。五章研判提示词为`codex-research-2`，材料比较增加`article-reading-scope-1`版本；标题比较保持原提示词。模型应把未读关键附件列入缺口，不能以链接名称推测条文。已排队的旧材料比较计划因执行指纹改变而失效，需要重新预览建批。

[本轮验收元数据](evaluations/article-reading-scope-20261003.json)记录4篇历史页面与2次有限本机Codex调用。段落核对仅比较空白归一后的包含关系；正文仍可能有多余空行，附件内容、表格及语义完整性未验证。实际模型输出是待本人核对的研究候选，未采纳、未生成订单，不能作为整体模型质量结论。

### 一份材料的多事项拆分

在“研究详情 → 材料与研究 → 一份材料中的多个事项”选择已保存材料，点击“使用 Codex 拆分事项”。每次仅发送所选材料及其范围记录，使用本机已登录Codex配置和账号额度；不是离线推理。后台保存冻结输入，可离开页面后返回查看；取消、失败或中断后不会自动重试。列表显示最近50次，数据库保留更早记录。旧材料已被新修订替代时，需先关联当前材料。

每项列出主体、动作、对象、阶段、原文引用、时间依据及事项边界。`material-events-2`还明确时间片段用途：发生/宣布、生效、到期/截止、涉及期间或待核，不能把截止日当作政策发布时点；旧诊断缺少用途时单独提示，原结果保留。相同政策下的多项措施不应机械拆开；不同具体决定可以独立追踪。至多12项，模型须披露可能未覆盖的范围，不能据此认定所有事项均被发现。原文引文通过逐字核验仍不证明事实、主体身份或拆分合理。零候选也保留范围说明和缺口。

填写逐项核对说明后，可排除、重新核对，或“为此事项建立研究”。建立的新主题为待核对、仅观察，引用同一不可变材料，来源获取时间不改写。来源研究、其他候选及原材料保留；创建主题与登记决定一起提交，失败一并回滚。同一已处理请求重送不会重复建主题。重新模型生成的候选未跨批次自动去重，请结合现有研究核对；共用一篇材料不能算多份独立证据。

材料或来源研究版本变化时，旧候选仍可查看但不能据此建立新主题。此前已创建的主题保留其冻结来源和核对说明，不被自动删除或重新解释；如需撤销，打开该研究按现有流程归档。拆分不会自动建立事件簇、关联证券、生成订单或改变风险限额。恢复副本核对前禁止发起调用及保存决定，离线演示不调用模型。

历史样本、调用指纹、时间用途修正与验证边界见[本轮拆分诊断](evaluations/material-events-20261003.json)。这些结果用于开发复核，不能当作独立模型效果或真实交易可用性的证明。


当前面板内切换拆分记录、刷新记录和提交失败会保留各事项尚未提交的核对说明；提交等待期间锁定表单，成功只清理提交项。决定版本改变后需重新填写说明。未提交草稿只保存在当前面板内存中，关闭面板或刷新整页前应完成必要的保存。

### 按拆分事项比较与归组

在“事件追踪 → Codex 语义比较”选择左/右侧事项，或在“持久比较批次”加入事项研究。事项来自“研究材料 → 拆分 → 本人核对建立研究”，未建立研究的候选不出现在列表。选择器显示事项、原文引用、时间用途与原材料；修订或校验失败的事项显示不可选，保留历史。

比较只针对选中的事项，仍冻结完整原材料供核对。两篇文章各含两个不同事项时，可以分别比较并在逐对一致、本人确认后建立两个事件簇；共用一篇材料不会把两个簇强制合并，也不增加来源数量。单次与批次使用同一本机Codex配置及持久租约，批次仍须预览调用数量及明确恢复调度。

事项v1是不可变拆分范围，不是研究笔记版本。保存研究关联或修改观察说明不会使它失效；归档该研究、丢失原引用或出现原材料新修订会使原比较和归组依据需复核。更新材料后须重新拆分核对；新事项不会自动替代旧事件簇成员，可按下节明确核对事项延续，或由本人另行处理原簇归档。旧研究、比较及事件簇快照不重写。整篇材料的比较不再自动归属到拆分事项，可在事项级重新比较并保存明确关联。

本批[官方材料诊断元数据](evaluations/event-scope-20261003.json)仅为3个开发配对：同一政策不同报道、不同政策跨材料、同篇报道里的不同工具。沿用先前样本与助手参考标签，不是独立样本准确率或前向有效性证明。


### 材料更新后的事项延续

先对新材料版本重新拆分并核对建立事项研究，再将对应新事项与保留的旧成员加入比较批次。新组全部配对有效且一致后，在“核对事件簇”下方选择原活动簇；逐项选择同一材料更新版本中的对应事项，点击“预览新旧事项对应”，核对两侧原文、主体、对象、阶段和时间，填写说明后“确认延续原事件簇”。全部成员都换成新修订事项时也须明确选择原簇，不能直接新建后再隐式合并。

延续保持稳定ID，增加簇版本并保存新旧对应与说明。旧事项研究仍存在，其关联事件入口显示原归属的历史版本；查看事件簇可展开全部历史与当时冻结的比较。事项v1与材料v2分别标明，不将研究笔记版本或新材料修订混为事项版本。原文、旧研究和原决定不覆盖，研究笔记不自动搬到新事项。

每个被替换旧事项只能对应一个同文档严格更新修订事项，所有其余原成员须保留。组内比较失效、映射遗漏或重复、目标已属于其他活动簇、恢复副本未核对均阻止保存。材料、比较或簇版本变化后须重新预览；失败不留下半份历史，重送同一成功请求不会重复增版。此功能依赖人工核对，暂不处理事项拆分/合并，也不自动识别证券主体或改变交易。

每次至多30项，逐项显示名称、原文、公司/产品等类型、单一/多个证券候选或未识别状态。目录没有覆盖全部市场，未命中不代表未上市；目录名称对应也不证明材料日期已上市、仍在上市或当时可交易。A/H/ADR不会自动选择一个市场，子公司、基金、品牌和产品也不能直接当作母公司证券。

可以排除、重新核对并查看决定历史。材料、事项或目录发生变化时旧输出保留但不能新关联；普通笔记更新不自动重跑模型，确认保存仍绑定当前研究版本。离开页面不会丢弃后台调用，失败、取消或中断不会自动重试；记录列表显示最近50次，数据库保留更早结果。恢复副本核对前禁止调用/决定，离线演示不调用模型。

证券选择和核对说明在当前身份识别面板内按记录、候选项和决定版本分别保留，切换记录或刷新列表不会清空。请求期间锁定选择与编辑，失败保留输入；成功只清理已提交项，新决定版本不沿用旧草稿。草稿尚未保存到数据库，关闭面板或刷新整页前需先完成正式核对。

### 按市场保存官方证券目录

自动事项身份另支持有界的同段上下文：原引文遗漏主体、同一段含原事项actor且引文唯一时，最多补回2400字符，并要求逐字原文和当前事项直接关系。相邻段、重复引文或过长段不自动扩张；产品名不直接等同上市公司。旧冻结范围保留，新范围仅由后台追加核对，个人编辑或拒绝仍优先。此为公司定位补证，不证明财务影响或可交易。

目录更新后的身份接续会按现有名称匹配规则比较实际依据；Nvidia/NVIDIA等价写法或解析器标签变化不会单独触发模型。升级前已排队但完全未调用的等价目录接续，可由后台保留原包并标明跳过重复；已发生的调用、附件接续与账户不受此处理。真正新增名称或证券依据仍沿原队列继续。

新自动研究冻结名称规则/2；旧/1回读保持。证券名称可在移除明确普通股后缀后，再有限移除法定后缀，保留原名及规则。Cadence短名另按[官方投资者页](https://investor.cadence.com/overview/default.aspx?lid=investor_relations)及[SEC申报](https://www.sec.gov/Archives/edgar/data/813672/000081367226000016/cdns-20251231.htm)核对；SAP名称与美国存托凭证按[官方FAQ](https://www.sap.com/investors/en/resources/faq.html)核对。补充简称只用于准确代码与目录名称，并记录2026-10-11核对时点；不是任意首词匹配或实时上市核验。新目录识别ADS/ADR并标明存托凭证候选，旧快照不重写；估值仍须独立核对币种、每股和存托凭证口径。

原已完成研究的身份缺口可在出现有效新名称依据后自动追加核对与研判，旧结果保持；仅解析器标签变化或相同已尝试依据不增加调用。目录排除命中、无精确名称、模型未确定与多证券歧义分别留档，最多20条排除明细并说明省略数。原重试、暂停及最终决定流程不变。


在身份识别面板展开“证券目录”，选择美股、沪深 A 股或港股，再明确点击获取按钮。查询、切换市场及打开历史版本不会抓取外网。更新按市场分别保存，但共用一次更新租约；失败不会清空该市场旧版本，也不会替换其他市场的目录。同一请求重送不重复获取，结果不明时重试沿用原请求。

美股沿用 Nasdaq 两份文本目录；沪深读取上交所主板/科创板分页与深交所 A 股工作簿、条数及上市日校验。沪深范围暂不含北交所、B股、完整退市名单。上交所响应没有可核实的生成日期，明确显示未知；接收时间不会代替生成时间。港股联合读取港交所中英文工作簿，核对代码、ISIN、买卖单位与币种，只把港币主板/GEM股票及预托证券类型作为待核候选；其他类型及非港币柜台保留原行与排除原因，不参与模型候选。

各版保存原始字节（工作簿以base64保存在本地）、SHA-256、请求/接收时刻、解析规则及原字段。工作簿读取限定工作表和大小，不运行公式、不跟随外链、不解压到文件系统。来源缺失、字段不符、分页或中英文身份不一致时整批失败，不把部分内容冒充完整版本。

来源生成日期晚于当前 UTC 日期的快照保留供查询，页面明确标示，当前模型继续使用此前可用版；没有可用版时沿用该市场有限手工目录。来源报告的未来上市日同样不进入当前官方召回。未来日期不是对文件真伪的判断；该日期到达后可参与当前召回，不回填历史。此前保存过未来日期文件，不阻止随后获取日期正常的当前文件；正常活动版本的日期倒退仍会被拒绝。

模型包按三市场可用快照做有界名称/显式代码召回，总计最多80项，保留各快照、覆盖及遗漏数量；未接通市场的手工条目独立保留。更新目录或召回规则可能使旧未确认候选需重新核对，已确认身份及研究历史不改写。新身份决定记录实际来源解析器版本，旧决定仍保留原标签和原始依据。公司名称、ISIN及报告上市日都不证明完整历史法律主体、母子公司关系或实时可交易性。

公司身份包 company-entities-2 为每个证券候选冻结 temporalAssessment（company-directory-time-1）：来源发布日期及精度、材料获取时刻、报告上市日、目录取得时刻与比较结果。日精度只比较来源日历日期，发布者时区仍未知；明确时区的发布时刻才换算为证券市场日期，包含美国夏令时。来源日期早于报告上市日仍可用于事后主体研究，但不能表示当时已上市；同日没有上市/开市时刻，晚于上市日也不证明历史法律主体或可交易性。材料发布日期不是事件发生或生效时间。

目录取得晚于材料获取时明确标明只可事后研究；此前已留存只证明在材料获取时可用，不证明在原文发布日期已可用。缺失、无效或精度不一致的日期保留未知，不用接收时刻填补发布日期。选择候选及关联后的公司关系均显示冻结时间依据，原目录与材料不写入这些派生字段。旧 company-entities-1 输出和已经关联的身份保留，未确认的旧包因时间契约变化失效，需重新识别后再关联；旧结果仍可读取、排除和保留原决定历史。


## 分钟统计异常观察

在研究的“观察条件”中选择“分钟统计异常”，明确选择关联证券、价格变化或成交量指标、历史基线样本数、标准差倍数和方向。每个配置版本仍只生成一条站内待办；重新监测产生新版本，旧待办、原样本及回执保留。观察不改变研究结论、仓位、审批或订单。

比较连续的分钟价格百分比变化，最新比较样本不参与基线，标准差分母为 n−1。基线为 5–120 个变化样本，因此需要至少基线数加 2 个价格，以及一个后续分钟记录。来源末尾采样始终排除；纳入样本至少已过60秒，最新纳入时点不能落后检查时间超过5分钟。同一市场、同一连续时段、严格相邻分钟才计算；不跨隔夜、午休、假期或收盘竞价，也不补齐停牌/丢包缺口。

必须由新适配器提供 minute-quality/1 解析依据。未知时区、旧缓存、无效或重复来源记录、窗口内非整分钟时间、零/不稳定标准差、失败/过期来源均显示无法判断。非整分钟的最后采样仍可显示在图表中，但不参与统计。保存后允许检查已有合格缓存，不声称当时已发现事件或恢复历史可交易性；供应商可能修订已保存价格，命中时已冻结的窗口不会随新行情改写。

分钟成交量仅支持 Yahoo 的 indicators.quote[0].volume 原始字段：须标明1分钟粒度，与时间数组逐项对应，窗口内各值为非负安全整数；不补零、不将累计量差分、不跨来源拼接或换算股/手。量基线为5–120个原始值，需要基线数加1个已结束样本及后续记录；候选不进入均值和 n−1 标准差。旧缓存、其他供应商、缺量或口径缺失显示无法判断。来源优先级保持原样，不为此自动追加请求；主来源价格成功但不提供核验过的量字段时，量条件仍无法判断。

这是一项研究统计，倍数不是置信概率或显著性保证。单位、供应商修订完整性和实时延迟未独立核验，量值不代表可成交数量；不能将此功能视为三市场实盘放量监控已验收。命中保存原量样本和口径，后续修订不重写待办。日线观察继续使用原来的日线规则。


时段沿用项目2026年研究日历，并保守排除A股最后3分钟、港股常规16:00后及半日12:00后的收盘竞价区间；这不是完整的市场执行日历。港股时段参见[港交所证券市场交易时间](https://www.hkex.com.hk/Services/Trading-hours-and-Severe-Weather-Arrangements/Trading-Hours/Securities-Market?sc_lang=en)。本轮上交所交易机制页可读，但其交易时段子页返回403，未宣称完整官方规则已重新验收。


## 备份保留与显式清理

`storage:preview` 继续只读。新增 `backup:prune` 分成计划和执行两步，不接入定时任务或容量告警。以下命令在 prototype 目录运行，路径替换为明确选定的库与备份目录；计划、回执放在备份目录外的新路径。

```sh
npm run backup:prune -- plan /path/research.sqlite /path/backups /path/prune-plan.json
npm run backup:prune -- apply /path/prune-plan.json <计划输出的准确planHash> /path/prune-receipt.json
```

默认保留最近 10 份，只有超过 30 天且在这 10 份之外的备份才进入候选；计划命令可在最后传入策略 JSON，字段沿用 `storage:preview`。容量阈值仅作预览告警，不会扩大删除范围。每次最多 100 份，计划 15 分钟有效。执行会重新核对路径、文件身份、清单、SHA、数据库完整性、外键、表计数、运行模式与首个不可变研究/账本历史锚点；候选或保留备份有变化时需重新计划。历史锚点用于保守筛选共享历史，不是全局唯一的数据集标识；操作前仍须核对所选备份目录。没有可用历史锚点时拒绝清理。

新建备份在独立目标文件内完成 WAL 检查点并切换到 DELETE 日志模式，然后计算指纹，因此是两文件快照；源库继续使用 WAL。旧备份含 WAL/SHM、未知文件、硬链接、符号链接、坏指纹或不同历史锚点时保留，不为满足清理要求自动移除这些内容。活动库本身不进入候选；备份文件不得同时作为运行库使用。

执行先在备份根目录建立 `.prune-lock`，将确认的候选移动到其中暂存，再次校验后只删除两个固定文件名。回执原子替换并同步文件内容，记录计划、暂存路径和逐文件删除结果。删除前的正常错误尝试移回；发生部分删除则保留锁和剩余文件，不自动继续。进程被强制终止后也需人工核对回执、锁目录与保留备份，不能直接递归删除残留；本轮未验证断电或所有文件系统的持久性。清理永久删除已确认的旧快照，保留快照可按上节恢复到全新路径，无法复原已清理快照独有的历史状态。并发备份可能使计划失效；该锁不阻止其他程序或同权限用户改写文件，维护时应暂停相关备份任务。

本批只验证合成临时库，没有清理个人备份、启用系统服务或执行数据库迁移。

## 从不同目录启动与数据库路径

启动器将 SIGNAL_DB_PATH 的相对路径按执行启动命令时的工作目录解析一次，再把同一绝对路径传给子进程；子进程切换到程序目录不会改变数据库位置。生产与开发模式都如此，启动日志显示实际绝对路径。长期入口仍建议使用固定实例配置或明确的绝对数据库路径，启动后核对实例名称与研究数量。

若旧启动器曾因相对路径在程序目录建立另一份空库，应先核对两份库及其历史，使用正确绝对路径或原固定实例入口；不要靠移动、覆盖或删除文件猜测恢复。路径修复本身不会迁移、合并或清理已存在的数据。


## 自动发现与研判队列

### 官方财务补证（美国证券候选）

持仓后续财报检查沿用同一开关和“自动研究”任务，不新增首页按钮或中间审批。实际持仓记录或市场模拟账户仍有非零数量，且该证券已有本队列自动保存的当前研判时，后台每6小时检查一次官方财务与申报来源；每次调度最多处理一个主题的一家发行人，其他工作轮流推进。账户名称、数量、成本只留在本地，本链路向来源和研究模型只传公开证券及研究材料。按证券选取相关研究不等于替换原建仓研究绑定。

只有原始来源内容、选摘事实、覆盖范围或读取规则变化才追加材料和研判；仅获取时间或选择窗口日期移动、内容相同，不反复调用模型。财务选摘、主申报和附件都使用原解析器核对完整原件；原研究与材料保留，新材料和新研判队列同一事务保存。调用额度用尽时保存证据并排队，沿用原额度与研判最多三次尝试；不增加预算，不自动买卖。

读取失败先等待60秒、120秒后重试，三次后本轮保留缺口并进入6小时冷却，原研判不覆盖；次数、下一次时间和检查结果写入持久记录，暂停、重启不清零。暂停财务开关保留已排队更新，恢复后继续。读取中清仓或本人编辑研究会阻止提交；未收尾读取在运行租约结束后显示中断。检查状态在自动研究API的 `events.holdingsFinancial` 返回，详细动作沿用后台审计记录。

边界：当前仅SEC美国证券，来源自身缓存继续适用（财务/目录6小时、映射/已知HTML原件24小时）；不是新公告必定6小时内发现的承诺。A股/港股、无当前系统研判的持仓、完整分部与市场预期仍有缺口。此候选使用隔离合成流程验证，不据此关闭三市场与长期验收。

“设置 → 自动化与运维 → 自动化设置 → 自动研究配置”新增“自动补充 SEC 官方财务披露（美国证券）”。新安装和旧库默认关闭；一次开启后，只对后续扫描的自动事项生效。关闭立即阻止后续财务读取和材料关联，已保存材料、研判和尝试记录保留。原配置请求省略 `financialSources` 时保留已有选择；该字段为布尔值，不改变滚动模型调用额度。离线演示不会访问外部来源。

后台在公司身份处理之后、该事项首次五章研判之前，逐证券补充财务背景。只使用 SEC 官方证券映射精确对应美国证券代码，要求唯一 CIK，且财务响应的 CIK 与发行人名称一致；不按模型记忆或模糊名称猜发行人。名称核对继续保留相同CIK和准确证券映射；仅名称主体逐字相同、末尾CORP / CORP. / CORPORATION写法不同可兼容，材料同时展示两份原始名称及规则版本。相容新材料使用独立/2记录，原逐字一致材料保持/1并可原样回读；不同公司及未支持差异仍保留缺口。此修复不重开三次耗尽的任务。当前映射不能证明历史身份、上市有效期或本事件与公司的关系，原证券关联仍为待核实。A 股、港股及未映射证券保留覆盖缺口。

使用 [SEC Company Facts API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) 和[官方证券映射说明](https://www.sec.gov/about/webmaster-frequently-asked-questions)。保留完整映射与财务 JSON、实际获取时间及 SHA-256，研究材料为 `excerpt` 程序选摘，不冒充完整财报或独立事实核验。保存材料、研究版本、补证覆盖和后续模型输入采用同一事务；材料回读重新核对原始响应及选摘，失败不生成半套研究依据。

选择范围为获取日向前 730 天内结束的期间，指定 16 个 US GAAP / DEI 标签，每个标签与单位最多 8 个最近期间。逐值保留标签、单位、起止日、申报日、表单、申报编号、财年 / 财期及 frame；同期间采用最新申报日，同日不同事实全部保留。旧期、其他标签、自定义项目、分部与附注不在选摘范围，缺失不补零。期间未推算季度或 TTM，不混加币种或替代收入标签；申报日不回填为系统首次获取日。当前汇总可能包含后续修订，只能按实际获取时间用于研究，不能重建历史可交易输入。现金、利润或 EPS 本身不证明回购执行金额、市场预期、估值倍数或目标价。

每次调度处理一家公司的补证；固定官方 HTTPS 端点，不跟随重定向；单次请求 20 秒、响应 12 MB 上限，实例内串行且请求至少间隔 1 秒。证券映射与申报HTML缓存24小时，财务响应与申报目录缓存6小时，原始响应不覆盖；HTTP 成功不代表解析或财务有效。沿用来源冷却：403 / 429 后 30 分钟不再请求，其他错误按原退避。每证券最多 3 次尝试（包括已开始但中断的尝试），失败按 1 / 2 分钟等待后重试；达到上限后带缺口继续研判，其他事项和调度路径继续。暂停、关闭来源、恢复核对锁、新闻修订或人工编辑均阻止迟到的结果覆盖研究。

材料详情沿用原证据入口，显示程序选摘范围和发行人；运行详情按事项显示补证结果与尝试数量，无新增首页面板或中间审批。现阶段只补充后续自动事项的首次研判，不回填旧研究；持仓按新财报独立重新研判、A 股 / 港股财务来源、完整分部与市场预期数据仍待建设。来源读取成功不等于研究质量、估值合理性或模拟成交已经验收。


在相同财务补证步骤内，进一步使用 [SEC Submissions API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) 的最近申报数组，核对 CIK、发行人名称和证券代码。选择获取日往前730天内最近一份10-Q / 10-K / 20-F / 40-F（包括修订），再选择不早于该份报告的最近8-K / 6-K（包括修订），最多两份；不遍历更早目录或修订所对应的基础报告。附件按下述范围另行读取。最新临时报告不保证与当前新闻相关，只作为待核背景。路径严格来自该发行人目录中的申报编号和主文档名；按[官方EDGAR路径规则](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data)允许申报代理的编号前缀，不凭编号前缀猜发行人。

完整HTML原件读取上限8MB，复用原始响应归档；`sec-filing-excerpts/1` 去除脚本及显式隐藏文字，沿用原表格结构提取器，最多500表、每表1000行、总计10000单元格与100000格位。普通网页读取仍使用原来的50表限制。程序从全部已提取文字中按固定财务词项选择完整文字 / 表格块，最多保留18000字符；单个超过预算的表格不截半拼入。记录规范化全文指纹、UTF-16选段位置、保留字符数与未选块数。全部HTML留存不代表全部内容已经研判，表格坐标不是原始财务事实，未读附件、遗漏分部、会计语义及单位仍待核实。最多8份已验证解析结果在进程内复用；每次不可变回读仍核验原始文件哈希，并重比选段结果。

如果目录或某份原件失败，沿用同一证券的三次总尝试，不另加无限重试。前两次等待恢复，最后一次允许保留有效财务数据和成功原件，明确记录其余缺口再继续研判；被暂停、关闭或版本变更打断的结果不能迟到关联。原件、材料、研究版本、读取记录与排队输入在原事务内接续，无新增人工采纳。原材料详情展示读取范围，原运行详情展示每份原件状态，首页布局及导航不变。

申报主文档读取成功后，后台从其可见正文中识别同一发行人、同一申报编号目录中的明确HTML链接。去除片段并按规范URL去重，按原文顺序每份最多4份（两份主文档加附件最多10份材料）；未选数量、排除链接数和无可用附件状态保留。只接受固定SEC HTTPS来源、无凭据或查询参数的HTML文件名；不猜文件名、不跟随重定向、不读取跨申报/跨域引用、PDF或附件内的下一层链接。后续若需更早材料，应另行明确读取范围，不能由“未选”推断内容不存在。

附件使用`sec-filing-exhibits/1`，同时绑定证券映射、最近目录、主申报HTML、附件HTML四份原始响应；材料回读重新校验全部哈希、父链接、选段及标题说明。每份附件沿用8MB原件和18000字符选段上限，来源日期仍未知；主申报的申报日不赋给附件，也不替代实际获取时间。规范化仅去除派生材料末尾空白以与原材料保存规则一致，原始文件、全文指纹和选段坐标保留。旧`sec-filing-excerpts/1`材料不重写。

附件失败与主文档共用该证券原三次尝试，成功响应缓存复用，第三次保留已读材料及明确失败原因后继续研判。暂停或版本变化不保存迟到结果；附件、主文档、覆盖记录与新模型包仍同事务保存。原材料详情可展开附件及范围说明，无新增首页按钮或中间审批。下载成功与同一申报身份只证明来源链路，附件与事件的相关性、法律/会计含义、未选全文及研究质量仍需核实。

### 显式自动模式（v0.13 开发候选）

配置本机 Codex 后，在首页点击“启动自动研究”。服务在同一事务启用系统研究策略并恢复 news / discovery 两项任务；保留来源开关、主题线索范围和每日调用上限，不启用执行或价格采集任务。点击“暂停自动研究”同时暂停这两项任务，已发起模型结果保留，后续处理等待恢复。模型未配置、离线演示、恢复待确认时不能启动。

只对后续扫描条目启用：正文 → 事项拆分 → 公司身份 → 系统五章研判。旧人工候选和旧队列保持原行为。0 个事项记为无信号，不继续调用；公司名称在冻结目录中唯一对应一个证券时，只追加未核实关联；多证券、未知主体、已有公司关系不覆盖。系统 actor / policy 与冻结输入、原文引用、模型输出和研究版本可追溯，不冒充人工核验。

正文准备、事项、身份及研判模型最多 3 次尝试，按 1 / 2 分钟退避，所有模型尝试共用原额度。身份耗尽可继续无确定公司的研判；其他耗尽保留观察。显式取消不自动重启。保存正文或公司关联后中断可续跑；来源修订、人工改动或配置变化保留旧结果。news / discovery 连续异常时按既有任务退避恢复，暂停优先；其他任务不改变。

POST `/api/research-automation` 提交 `{action:"start"|"pause",version:<当前配置版本>}`。配置接口允许追加 `automatic,extractEvents`，自动模式要求拆分启用。HTTP 来源、实例、恢复门禁与最终订单批准保持原规则。系统中间候选从人工待办移出，观察缺口和过程仍在研判 / 队列 / 日志可查。

自动事项研判完成后，遍历当次全部活跃已选事项，保存有限词项召回命中的完整候选清单，按每批3项自动续查；自动比较仍仅使用已保存的事项范围。明确的成对结果经原校验保存为系统关系判断；无法判断转观察，已有人工或其他成对决定不覆盖。支持重复、进展或反向变化时，可建立首个双成员事件簇；扩展包括原簇全部成员，只有每一对同事件判断一致且版本仍有效，才保存系统事件簇或新版本。既有配对按完整输入、方向、模型和决定复用；反向触发保持原簇成员顺序，不重算已采用的比较。来源、关系、配对、事件簇及历史引用都保留，不生成订单。

关系和组内比较失败最多三次，按一分钟、两分钟间隔退避并计入同一滚动额度；单批次暂停 / 取消及整条任务暂停都阻止后续推进。旧簇不因冲突或重试耗尽而缩减，其他材料继续。额度耗尽或模型被占用，不阻止其他阶段保存已完成的结果。成对决定与队列状态、事件簇版本与成员 / 命令 / 队列状态在同一事务提交，存储失败可续跑而不重复调用。系统关系与批次不进入必须人工核对的工作台待办，运行详情显示真实状态、观察原因与系统来源；原手动入口仍可查询和纠错。

来源修订完成新版研判后，可在完整一致与唯一对应条件下延续原事件 ID，并将旧研究保留于事件历史。没有可用保留成员或同一文档多个旧事项时，后台先完成旧事项 × 同文档新候选的全部比较，再独立检查新版全部成员；未知、歧义、多对一或比较缺失保留观察，其他来源继续。依据在原事件簇历史中按需展开，不增加中间确认待办。

自动归组不再受手动十份当前输入限制，旧新矩阵也不再以二十份输入停止。内部系统任务冻结全体成员和全部配对，复用指纹、方向、模型及决定一致的结果，逐项调用缺失比较；额度耗尽后等待额度恢复，重启沿原计划继续，不要求本人拆批。完整配对及唯一对应条件仍全部检查，尚未完成时保留原簇。普通手动选择仍为2至10份，HTTP字段不能伪造内部系统能力。

升级时仅对原自动任务明确因上述数量上限停止的条目追加一次恢复计划，保留原停止记录与关联，并重新验证现行输入及决定；人工、取消和其他观察不因此重跑。旧输入已经变化时保留失效原因。已存在的运行批次按原冻结计划继续，不重建已完成比较。

有限召回、不自动跨簇合并以及综合材料包大小限制仍各自适用。完整配对计算量为 n×(n−1)÷2；11成员需要55对，11旧×11新需要121对对应后还需新版55对。这是可持续排队能力，不是吞吐或质量保证。大规模数据库 / 页面性能、完整外部补证、真实增量运行和独立质量仍待验证，因此仍不是完整 v0.13。合成测试不证明分析正确性或策略收益。

进度汇总只读取批次持久状态、配对总数及复用数量，不重新展开每一对模型输入；“候选数量”不等于比较已采纳或归组已保存。完整查看、关系采纳、修订对应和保存仍执行原校验。已结束的语义投影最多256项并受16 MiB序列化内容预算约束，写入 / 其他连接提交 / 结构变化即失效，事务内及运行态禁用。事件簇纯校验另按刚读取的完整字节复用一份结果，内容、归属、材料或研究变化仍拒绝；超过16 MiB不保留原字节缓存。数据库表、原快照及历史不改写。

### 事项召回范围与自动续查（开发候选）

自动模式新增 `research_relation_scans`，冻结来源研究 / 新闻版本、规则和比较配置指纹、范围统计、排序后的轻量候选清单；每次只准备下一批最多3项的完整比较包，进度与该批计划在同一事务提交。已有关系记录、取消与决定不覆盖。无剩余候选只表示安排完成，比较、观察、失效和未安排分别显示；新事项不悄悄加入旧范围，由它自己的研判追加比较。

目标的自动研判尚未完成时保留缺口，待目标完成后接续早先匹配，即使反向词项检索未命中也保留这条线索。源研究、新闻、模型 / 提示词 / 规则发生变化时原范围停止续查；目标单独变化保留该项失效并继续其他目标。升级只给仍为原系统版本的旧自动研判追加一个范围记录；人工候选不回填，既有比较不会重跑或覆盖。

自动调度持久保存轮转位置，让正文准备、事项 / 公司 / 研判、关系比较、完整归组和综合分别获得处理机会。额度不足或模型忙时仍可保存其他已完成结果；额度恰好在两批间耗尽时显示等待额度，而非没有待办。归组与接续等待有关来源的召回批次结束，复用现行完整比较；同时修订按实际系统研判完成顺序保留比较方向，通过完整新旧对应后可一并延续原事件 ID。

原“运行详情 → 自动化设置 → 自动关联比较”新增可折叠的范围与续查数量；事项任务也显示同一统计。首页与导航不增加按钮。该范围不等于全网覆盖或语义召回率；原人工模式仍最多索引500项、选择3项，下节已收新闻补证的2000 / 500 / 3边界不变，综合材料包限制仍适用。

### 已收新闻的自动补充依据（开发候选）

系统事项研判存在 `missingEvidence`，或自动条目读取正文失败时，discovery 调度会检索已经接收的相关新闻。每次最多索引最近入库2000条新闻的当前版本；研究范围最多500份当前系统事项与500条正文失败记录；按现有有限词项规则、90天发布时间窗口召回并选取前三条线索。检索范围、缺口、选择理由和各次结果保存到 `research_evidence_searches`，新相关输入追加记录，未命中不表示没有证据。没有新匹配时不反复生成同一检索或重复调用模型。

候选须在初次扫描时就属于自动模式。原本 `skipped` 的条目可以因补充研究进入既有队列，原初筛内容、规则和入库审计不变；旧人工模式条目、已有人工作品或取消的条目不重新激活。新闻正文使用原安全读取器，不把标题当正文、不猜测新的URL。额度不足等待原额度恢复；正文与模型失败沿用三次重试和退避，未完成原因留档。

补充材料先识别事项、公司并保存系统研判，再明确核对原事项，不能因普通召回前三项中没有原事件而漏掉对照；复用已有配对，不重复调用。部分事项失败时保留已完成的可比事项，并标明范围缺口。明确同事件的配对继续经过全成员一致性检查和综合研判；相关、类比、不相关、未知与失败分开保存。原文不可用时，替代来源只形成独立研究，不能宣称还原了原报道。

“运行详情 → 自动化设置 → 自动补充依据”可查看当时缺口、实际检索范围、入队理由、事项引用和旧记录，展开后下钻到原材料 / 事项研究，再返回保留原选择、展开与滚动位置。只读页面不会执行新检索。检索处理完成不是缺口核实；全网搜索、公告附件、财务敞口专项补查和真实效果验收仍待完成。

### 兼容的旧候选模式与关联比较

以下“本人选择 / 采纳”“失败明确重试”描述旧候选模式；新自动条目的事项、身份、研判、关系与事件簇按上一节处理；下方保留旧候选模式的行为及范围说明。

标题初筛0.5.1补充针对具体主体的金融监管执法与整改公告：进入待研判候选，重大性与方向仍未知；拟议和否认分别标记，会议、培训、程序说明不因含执法词汇提升。规则升级追加留样，保留旧队列与研究；已存在的同版研究沿用原保护，不覆盖。

配置已有本机Codex后，在运行控制查看自动研究队列并调整调用上限；默认暂停，明确恢复“自动发现与研判”后每10秒检查。默认选规则初筛重大候选，可加入主题线索。筛选与事项选项只影响后续扫描，已有未选中记录仍供漏筛复核；调用上限立即生效。

选中新闻先建立仅观察研究、读取公开正文，再调用Codex。聚合入口、受限页面、无足够正文或来源变化时条目失败，原记录保留；不把标题当全文。同一新闻版本已有研究时保持待核对；来源修订建立独立候选，原研究不覆盖。到对应研究查看模型候选，采纳仍沿用本人复核流程。

滚动24小时默认最多10次，可设1–100；失败调用和显式重试计入。暂停阻止新准备/调用，已启动模型结果仍保存。读取中暂停不保存迟到正文，中断条目可明确重试。重启不重复已关联run；模型、提示词或读取器改变时停止旧条目，需核对配置。自动关联比较与自动研判共用此调用预算和模型租约；手动研判与手动比较批次独立计量。

自动模式下，同一来源最多三对事项关系可合并为一次模型调用，每对的全文、范围、引用、原方向与判断都保留；材料过大则缩小组合或单独调用。预算按实际调用次数计量，运行详情另外显示“关系调用次数 / 配对尝试次数”，两者均包含失败；首次共享调用失败后拆回单对，分别沿原上限重试，不让一对输出错误阻断其他配对。旧比较和手动批次沿原规则处理。共享调用的原始输出和轨迹随各对保存，输入更新只使受影响的配对失效。取消同次任意一对会终止整次共享调用，按钮及详情明确显示影响的配对数；暂停只阻止后续启动。此优化不会减少原定比较范围，不能据此声称模型质量或真实吞吐达标。

GET `/api/research-pipeline` 查看队列；PATCH 同路径提交 `version,dailyCalls,includeClues`；POST `/api/research-pipeline/:id/retry`（空对象）重试失败/中断/取消项。既有 `/api/operations/discovery` 控制任务；实例身份与恢复门禁沿用既有HTTP保护。

新报道保存正文后，会在现有事件追踪索引中召回相关研究，从最多5个标题/来源/有限实体目录命中中排除自身与归档研究，选择最多3项。每侧采用最后关联的保存材料，保留摘录/网页提取/人工文本范围；缺少材料、相同材料或重复材料对只记跳过，不以标题代替正文。索引覆盖最多最新2,000条新闻和500份研究；界面显示本次覆盖，未命中不能解释为没有关联。

比较计划与研判run在同一事务冻结，后续周期优先逐项比较，再准备下一条新闻。计划记录新闻和研究版本、材料快照、召回依据、提示词/schema/配置指纹；调用记录、队列与租约一并提交。只产生待复核语义候选，不自动采纳、合并研究、向旧研究追加证据或改写五章研判。无关与无法判断结果同样保留。来源、研究、材料或配置变化，以及本人排除该召回线索后，旧计划停止执行；失败不自动重试。

运行控制的“自动关联比较”显示最近30项、关系理由和双方引用；完整结果仍在事件追踪的语义比较中复核。POST `/api/research-pipeline/relations/:id/retry`（空对象）只重试仍适用的失败/取消/中断比较，保留旧run与调用次数。原有队列条目不会因升级自动补建比较计划。跨报道的多事项自动对应与独立质量验证仍待完成。

“自动拆分正文，并续写已选事项”默认关闭，打开后只影响新入队新闻。来源正文保存后，队列冻结一份拆分计划，在后续周期复用本机Codex材料拆分，输出0–12个事项候选。来源整体研判与事项拆分各自保留，不自动把模型划分写成已确认事件。到来源研究的材料面板核对后，可逐项建立观察研究或排除。自动队列只发现这些已记录的本人创建决定，为尚未编辑的初始事项研究生成五章候选；不会代替本人选择或采纳。

来源研判、材料拆分、已选事项研判和关联比较共用滚动24小时调用额度。拆分/事项研判先于关联比较推进，每周期最多启动一个模型调用。筛选与事项选项只影响未来入队，已有计划保留；调用上限立即生效；要停止后续调用，暂停自动发现任务。空拆分、失败、排除与历次调用保留，失败需明确重试。POST `/api/research-pipeline/events/:id/retry`（空对象）重试仍适用的失败/取消/中断条目。

事项续写核对原拆分run、本人决定、初始研究版本、原文引用、当前材料与执行配置；已编辑、归档或依据变化的事项停止自动准备。事项范围约束自codex-research-3引入，明确只研究选定事项，原文其他事项作背景，截止/生效/期间不冒充发生时间；旧结果仍保留，新提示词不会静默用于旧等待条目。执行指纹包含稳定输入及提示词，材料包的生成时间仅为包装时间，不因等待额度跨天而使未变证据失效；原文发布时间、可用时间与本人决定时间仍受校验。新流程尚无独立质量结论；跨报道事项对应与簇更新的覆盖和独立质量仍待验证。

同一来源的新修订采用独立观察候选及来源谱系：新候选保存上一研究的ID、固定研究版本与新闻版本，旧研究、材料和模型结果不改写。正在跟踪的来源修订即使未再命中重大标题规则也进入队列；未跟踪的普通新闻仍按原筛选选项处理。同一新闻版本已经由本人建立研究时停止自动准备，避免替换手工内容；手动从修订新闻建立研究也按当前版本定位，不返回旧版本研究。

新研判材料包的sourceRevision只提供上一研究固定版本的正文与旧判断，明确标为历史对照，不是当前事实或新增独立证据。历史材料共用内容与元数据指纹校验；新增的旧版本读取只用于这个历史上下文，普通语义比较的当前版本要求不变。提示词codex-research-4要求分别识别新增、删去、反向表述、阶段变化及未改变内容；证据不足仍记未知。原文过大或历史快照损坏时停止候选调用，不截断后冒充完整。

自动关联若召回已选定的事项研究，必须使用event范围与原事项引文，不能拿整篇来源代表其中一个事项；旧计划若缺少事项范围则停止。跨报道事项对应和事件簇增量的候选流程见下文，相关质量仍需验证。

已选事项开始自动研判时，会按该事项自身的标题、主体、动作、对象和原文引文召回其他报道中的活跃已选事项。最多索引最近500项，共同有效词项至少3个且覆盖当前事项词项35%，按重合数和稳定ID排序，选最多3项比较。此规则只负责缩小候选范围，不判定事件相同；整篇背景不加入事项召回，同篇来源及共享材料排除，双方引用仍经既有event范围校验。覆盖与计划数量显示在事项队列，比较详情在自动关联比较中。

比较计划与事项研判run、队列及调用计数同一事务保存；失败回滚不留下孤立计划，重试沿用原计划，不扩张目标。后续比较共用自动调用预算，材料或研究失效时停止。已完成的旧事项不因升级回填新计划。当前是有限的跨报道事项对应候选，事件簇增量候选见下文，独立语义质量尚未验证；共享文字或来源标签不能证明独立取证。

事件簇增量候选：新建事项自动比较计划带入扩展资格，旧完成计划不回填。比较支持重复、进展或反向变化，且目标属于有效已确认事件簇时，自动建立“新事项＋原簇全部成员”的完整比较批次，最多10份输入。超过上限、尚未归簇、依据失效、已有同版本计划或新事项已经归簇时记录具体原因，不截断成员、不自动跨簇合并。

仍有效且方向、完整材料包、模型和决定匹配的原配对会复用，保留原run与引用，不增加本次调用次数。其他配对逐个调用，共用自动研究的额度和模型租约；批次明确标为自动研究所有，普通“持久比较”任务不能执行这些调用以绕过额度。可以在批次中暂停、取消和显式重试；失败不自动重跑。自动发现暂停会停止后续推进。

运行控制展示事件簇增量候选、原簇、批次ID、复用数量及停止原因。在“持久比较批次”打开对应批次，核对全部配对，再点击“核对事件簇”确认新版本；任何缺失、冲突或失效配对都沿用完整组内一致性校验。确认沿用原事件簇ID并增加不可变历史版本，不修改原研究或产生交易。事件簇版本、来源或触发决定在等待期间变化时，扩展停止并暂停批次；不能用旧计划继续补齐新成员。此流程尚未证明跨报道对应质量，也不自动解决多簇冲突或失效事项的人工继承映射。


## 前向调用档案

研究模式配置本机Codex后，在“研究评估 → 前向调用档案”填写名称并明确启用。此动作只冻结基线、开启以后单篇研究与事件综合五章研判的登记，不发起模型调用；暂停后旧档案保留，重新开始须冻结新的基线。全部来源时间与成员版本由服务端读取，流程与独立效果验证的区别见[评估协议](EVALUATION-PROTOCOL.md)。

同源且通过实例校验的本机API：`GET /api/forward-evaluations`返回最近50个基线、100次调用及总数；`GET /api/forward-evaluations/baselines/:id`读取完整冻结基线，`GET /api/forward-evaluations/records/:runId`读取调用依据与校验状态。`POST /api/forward-evaluations`仅接受`requestId,title`；`POST /api/forward-evaluations/pause`仅接受当前`baselineId`，过时基线不能暂停新基线。完整基线含本地研究/来源快照，只在本机保存和核对，不加入公开源码或截图。

新增`forward_baselines`与`forward_captures`表随既有SQLite备份保存；恢复核对前不接受新的业务写入。源码运行中发生变化时先重启对应候选，再冻结基线；模型配置或代码偏离原基线的调用会留下排除原因，不静默更新原基线。此功能不代替Mac常驻启用、个人实例升级或长期运行验收。


前向调用详情可展开“登记复核标签与主张结局”。只有原调用中的主张可以登记结局，新增预测应在研究中另建并进入后续调用。结局材料先保存到原研究，再刷新复核档案选择版本和逐字引文；材料原文及修订留在本机。结局时点未知可留空，未解决和部分兑现不作二元评分。

`GET /api/forward-evaluations/records/:runId/review`返回冻结主张、复核版本和历史；同路径`review-inputs`对单篇返回原研究当前关联的可选材料及不可核实项，对事件综合返回调用时冻结的原文版本；综合没有独立概率主张，不移用成员概率。`POST .../:runId/label`和`POST .../:runId/outcome`仅接受`requestId,version,value`，服务端追加新复核行，不修改研究、模型run或市场账本。新`forward_reviews`表随SQLite备份，恢复核对前禁止写入。页面未知保存结果可原请求重试，版本冲突保留草稿并要求显式载入新版；不自动提交，也不自动认定独立验证通过。


前向档案的“固定窗口报告”选择基线与已结束的本机时间段，保存全部调用、失败、排除和当时的复核版本。此操作不启动模型、不改研究，不自动开启前向登记。旧报告保留，后续更正需要另存报告。

GET /api/forward-windows 返回最近50份摘要和总数；GET /api/forward-windows/:id 读取完整本机报告，可按ID读取更早报告；POST /api/forward-windows 仅接受requestId,title,baselineId,start,end（API时间须带时区）。完整报告含私有基线、输入与结局引用，不应复制到公开PR。窗口最多5000调用/64 MiB，超限要求缩短窗口，不截断。新增forward_windows表随SQLite备份；恢复锁、实例校验、同源和请求幂等沿用现有流程。源码改变需重启完整候选后再冻结报告。


## 跨主题共同风险复核

观察任务同时检查两池的当前持仓和已批准未完成买单；若不同研究共享已核验发行人或当前有效的已确认事件簇，在“观察待办”生成“跨主题共同风险复核”。展开后可分别查看策略池、研究版本、持仓/买单剩余数量、观察估值与关联依据。买单估值不是实际持仓或成交承诺，缺失价格/FX显示未知。每组单独统计，共享发行人和事件簇可能覆盖同一批记录，不能把多条待办金额相加。

重复检查不重复生成待办。数量、研究版本或关联变化形成新轮次，旧待办与回执保留；行情或关联失效显示无法判断，不因完成回执而解除风险。持仓归属沿用成交时发行人；新行情身份不一致需要核对。此功能不调整订单、暂停、原有仓位限制或两池资金，尚不覆盖未识别的宏观、行业和供应链关联。


## 主张与交易假设草稿

“概率与影响”和“交易假设”未保存输入保存在当前标签页的会话存储；关闭研究面板、切换标签或刷新可恢复。会话结束、关闭标签页或清除站点存储可能丢失，不能代替保存；SQLite备份仅包含已保存研究及历史。存储不可用时界面提示仅在页面内保留。

其他窗口保存新版后，旧草稿保留原版本并禁用提交。先查看历史：主张可丢弃后按新版重新编辑；假设可明确核对后保留输入继续编辑，或丢弃并载入最新版本。这不会自动提交交易或改写旧历史。本轮覆盖这两个编辑器，不代表所有表单都有相同保护。

新建主题、补充手工证据和人工核验也保留标签页会话草稿；核验按证据分别存放。证据或核验出现版本冲突时，先核对历史，明确丢弃后按最新研究重新编辑。关闭表单不丢弃草稿，成功保存或点击“丢弃”才清理对应草稿。网络结果未知时，创建主题可能已在服务端完成，应先查看研究列表再重试；此功能未新增创建请求幂等。

正文材料草稿同时保留粘贴/网页导入方式及原研究版本。核对历史后可明确保留正文继续编辑，也可丢弃并载入最新版本。新闻关联的说明按目标研究分别保存；“刷新新闻版本”读取本机最新修订，来源或研究版本变化会禁用旧稿提交，须核对后明确丢弃重编。上述草稿仍受标签页会话寿命和浏览器存储容量限制，未保存正文不进入SQLite备份。


初筛复核也保留标签页会话草稿；“刷新初筛复核”读取服务器新记录，其他窗口已追加复核时保留原输入并禁用保存。核对下方复核历史后，可“丢弃初筛复核草稿并载入最新版本”。新闻修订或规则升级分别形成留样；通过“初筛留样版本”选择当前页的最多12份，用“上一页留样 / 下一页留样”查看更早记录；分页固定本次范围，“回到最新留样”重新加载新增记录。核对原始标题后继续复核或找回草稿。保存复核追加历史，不覆盖来源留样；尚未保存的草稿不进入数据库备份。


市场模拟中的发行人身份与已成交持仓、原批准快照绑定。相同代码的新行情若报告另一发行人或原记录缺少身份，相关成交显示等待；持仓金额、净值及相关价格风险保持未知，不能通过当前行情重写原身份。身份恢复且全部原执行条件仍满足后才可继续。待成交买单的跨主题归组也沿用批准身份；cross-theme-review/2可产生新规则复核轮次，旧待办/回执及已保存账本历史不改写。公司行动造成的合法身份转换尚需专门迁移流程，此处不自动映射。


## 网页表格与材料修订

public-article-5在正文原位保存Readability保留的HTML表格。`[HTML table …; html-table-text/1]`块中，r/c为从1开始的行列，冒号表示合并格覆盖范围；单元格文字使用JSON转义，th/td保留原标签。空单格省略文字但仍占位，空合并格保留跨度；括号、横线和零保持原文本，嵌套表有独立编号。坐标及块标记由提取器添加，不能当作原公告财务文字或独立证据。

每次最多50表、每表1000行/256列、总10000格及100000占位，结构化正文仍受8万字符上限约束。非法跨度、重叠格及Readability保留孤立行/格而丢失表容器时拒收，提示核对原表并补充必要摘录，不保存猜测结构。该保护只适用于保留HTML，不保证Readability未遗漏其他内容、CSS显示顺序或附件完整。

重读内容变化追加材料修订，旧正文、来源检查及研究历史不改写；旧扁平表不补造行列。研判与材料比较使用相同保存正文，阅读范围版本2及五章提示词codex-research-8使新输入可追踪。财务表头与数值分散时，现有逐值原文字面检查尚不自动组合币种/倍率，也不会因模型能读表就放宽“一致”的明确金额引用门禁。模型结果仍为待核候选。


## 完整窗口采集报告

进入“数据源 → 新闻入口与覆盖记录 → 按窗口核对采集记录”，选择UTC开始与结束日期（包含结束日），点击“生成覆盖报告”。最多31天，统计窗口内开始的全部采集尝试，不按新闻发布日期取数，也不会补采；不会随页面轮询重复扫描。

报告按入口显示失败/部分/中断/执行中、重复与截断、逐日没有尝试或没有成功的日期，以及关键词/适配版本/收取类型。原始/接受/新增等为各次返回计数相加，唯一标题与修订仅依据已保存观察关联；老记录缺失计数字段单列未知，缺失观察关联不能推导为从未收到新闻。最长无尝试间隔包含窗口边界并截至生成时间，不能解释为缺失新闻数量。报告中的当前配置不能还原历史启停，停用来源和旧查询记录仍可出现。

只读API为`GET /api/news/coverage?from=YYYY-MM-DD&to=YYYY-MM-DD`。单次读事务保证报告输入一致；报告提供生成时刻、窗口和输入指纹，不持久保存报告版本或返回原始响应。现有限额为25万次尝试/100万观察关联，超限会要求缩小日期范围而不会静默省略。数据库中的原始响应、逐页记录与旧材料均不改写；报告不是全市场、所选来源或历史档案完整覆盖证明。

## 容量监测

实际服务入口注册“容量与保留检查”，首次为暂停。在运行控制中可恢复、暂停或重新检查；启用后每小时运行，离线演示也可执行本地检查。扫描有60秒取消信号，失败沿用有限重试；它只记录测量，不删除文件、不建立缺失目录、不修改保留计划。

范围为当前数据库及旁文件、数据库父目录下的backups；该目录可包含其他实例备份，不是全项目附件/日志总量。磁盘可用数值来自数据库所在文件系统。默认保留最新10份和30天内备份，备份1GiB和磁盘余量1GiB只是提醒阈值。候选不是已获准删除的清单，实际清理仍走显式计划/确认流程。

结果存于storage_checks，包含策略版本、范围指纹、起止时间、测量/候选数量及分类告警；完整历史留库，界面显示最近20次。失败不替代成功测量，超过两次间隔或恢复到其他路径有提示。读遍备份检查SHA不能替代完整性和恢复验证。进程退出前来不及保存结果时，以任务中断记录为准。恢复保留历史并暂停任务；核对确认本身不启用检查。

## 待办历史与处理说明

观察待办默认显示待处理（含已读），可切换已完成或全部历史。每页最多50条，翻页保留本次新记录边界；“刷新到最新待办”纳入后来新增项。处理状态取读取时当前值，因此完成后当前筛选页可能变少，可返回前页或刷新。所有旧待办及回执持续留库，完成、重开不会删除冻结依据。

工作台摘要包含数量/状态及变化标识，不再附全部待办正文。只读接口为`GET /api/observations?state=pending|completed|all`，后续页携带返回的`ceiling`和`nextCursor`（作为`before`）；不得把第一页当完整历史。原单条回执接口保持不变。

输入的处理说明在此弹窗内跨页保留，关闭前应提交回执。草稿绑定输入时revision；并发变化或过期提交被拒后，可查看回执、明确核对并保留原说明，或者丢弃。核对不会自动提交回执。已读、完成与重开只改变待办处理状态，不执行交易、解除风险或修改原研究。


## 本机历史类比检索

在新闻详情展开“历史类比”，点击“检索并保存历史类比”。报告扫描本机库全部当前新闻修订，不限90天，也不受最近新闻列表截断；按七类有限标题机制和共同领域/发行人线索列出待核对案例，不自动合并事件或生成交易。每页25项，年份、来源修订、实际接收时间与差异保留；“已保存检索”读取旧报告，“导出本次完整检索”包含全部输入、未入选原因及代码快照。

报告保存在当前SQLite数据库的historical_recall_reports表，随一致备份恢复。新检索追加，不覆盖旧报告或新闻历史。超过20,000条新闻、12MiB原始标题记录或32MiB报告时拒绝生成部分结果。完整候选源码与评估协议必须随安装保留；源码变化后先重启服务再生成新报告。最小运行包缺少源码时仍可查看旧报告，但不能新建完整档案。标题规则遗漏和错误类比仍须结合原文核对；没有结果不表示没有历史案例，不提供历史可交易性或收益证明。


### 从已保存正文查历史类比

研判草稿现使用包含实例身份的v2会话键；切换数据库后，即便研究来自同一副本，也分别恢复各自草稿。升级前v1草稿没有数据集标识，会单列为“旧版研判草稿”，不自动填入。核对预览和当前数据集后可明确载入；已有未保存草稿时先保存当前输入或手动复制所需内容，避免覆盖。旧原件仍保留在原浏览器会话，未自动迁入数据库；载入保留旧基础版本，必要时仍需核对新版本。无法解析的旧记录不会被删除。此为浏览器草稿格式升级，无服务器数据库迁移。

## 固定价格窗口的持久采集

3. 在新的固定测试实例、独立恢复路径和独立端口验证最终候选；确认恢复状态期间不启用采集、模型、模拟执行或清理。初始化允许的新增结构/行与旧行保持分别报告。

6. 核对和确认后再运行旧版本，检查新确认审计/核对标记及正常巡检记录等预期写入；源快照保持不变。旧版本的未确认tick已复现更新事件巡检时间，因此它的待核对状态不得当作只读运行保证。

## 实际净值采样与参考收益

本地候选复用原 observations 任务和实际估值门禁，为逐笔账本账户保存原币净值。正常至少间隔60秒；账本 / 报价改变即时留样，未知重复状态每个账户当地日只记一次。同一时刻的新输入保留新旧两条，仅最新点参与计算。实际记录与市场模拟 / 结构演练账户完全独立；查看网页不写采样、不触发交易。

`actual_nav_samples` 随原SQLite一致备份，保存引擎版本、账户、时间、账本有效前缀、现金、参考净值、每项报价及来源指纹、缺口和记录摘要。读取校验存储摘要；恢复待核不采样。时钟倒退或任一账户写入失败整批回滚。该事务仅涵盖净值采样，不与此前研究巡检合称一次事务。

按相邻有效点计算 `r = (V结束 − V开始 − Σ外部净流入) / (V开始 + Σw × 外部净流入)`，`w = (区间结束时间 − 资金流时间) / 区间时长`；金额在整数分、时间在毫秒内核算，最终比率才转换。外部流入是入金，出金为负；买卖、股息和费用已经反映在账户净值。链结区间因子形成首点100的参考指数。计算原则参见 [GIPS 官方手册对 Modified Dietz 的说明](https://www.gipsstandards.org/standards/gips-standards-for-firms/gips-standards-handbook-for-firms/)；本实现采用实际记录时间权重，仅作近似研究参考，不宣称精确TWR、券商收益或GIPS合规。大额资金流和剧烈波动会扩大近似误差。

补录、修订或撤销改变某时点之前的有效账本时，该采样保留原值并标为不参与；不会按当前行情重写历史。现金 / 数量对账调整及无有效正资本等情况建立新的比较窗口，旧窗口仍可查看。有效端点之间可核对整个区间损益，但中间未知点不插值，曲线在缺口与窗口切换处断开。采样回撤仅以该窗口的参考指数高点比较，不推断未采到的市场高点或完整历史最大回撤。

首页的“今日采样变化”从账户当地今日第一个有效点起扣除出入金；CNY用上海、HKD用香港、USD用纽约日期，不是开盘以来的完整交易日损益。当前 / 最大采样回撤、区间参考收益需至少两个有效点。巡检暂停 / 失败、输入变化、估值失效、采样超过2分钟或恢复待核时，当前指标未知；原记录仍在。

在“组合 → 实际持仓记录 → 逐笔账本 → 账户核算依据”查看摘要，再展开净值路径、资金流及每条报价依据。`GET /api/actual-performance/actual:<账户摘要>` 每页60条，以 `before` / `ceiling` 固定新增边界；不接受浏览器上传净值或报价。已打开页保留读取时状态，后台或账本改变提示刷新；跨账户迟到结果不显示成另一个账户。本候选完成合成公式、边界、持久化、HTTP及页面验证；真实对账、长时间大量采样的响应与存储成本仍需单独验证。


### 长历史计算与缓存边界

净值汇总在进程中保留可重建的计算状态；每512条保存一个分段状态，历史页面从相邻分段继续重算，只把本页60条原始报价与资金流返回给页面。纯顺序追加时只核验新点，热读取仍重新检查当前行情、巡检状态、恢复锁和时间；不因缓存延长报价有效期。进程重启、缓存被逐出或历史事实变化后重新读取并校验全部受影响账户历史。最多缓存8个账户；这是内存缓存上限，不是账户数或历史记录数的业务限制。

新增 `actual_nav_epochs` 和采样表 INSERT / UPDATE / DELETE 触发器在同一事务更新账户修订标记。其他连接写入、同刻更新、非顺序补录、替换 / 删除均重建相应计算；回滚也回滚标记。原账本事实指纹变化同样重新核验。缓存不写入账户事实、不覆盖历史、不生成订单；原采样摘要仍校验，损坏时不返回过时缓存。查询索引覆盖账户 / ID与全局采样时间；这些索引和标记随原库备份，恢复核对规则不变。

后台对已纳入当前系统研判的明确附件逐份核对公司身份，复用原身份与研判队列、共享额度及重试规则，不增加中间确认页。原事项动作与对象仍固定；新 company-attachment-entities-1 输入同时保存附件正文、原事项引用和具体文档关联。候选逐项区分直接关联、背景提及、其他事项、关系未知，直接关联必须提供两边的原文依据和关系理由。引用校验只证明原文存在，不证明语义判断正确。

仅直接关联且原文名称在当时目录中唯一对应的公司可自动成为待核实关系；已有公司不重复添加，子公司不能推测为母公司，多市场歧义保留。新增关联后补齐该证券缺少的已配置价量与财务输入，再自动更新同一事项研判；没有新增关联时保留原研判与未知项。相同附件可服务多个事项，但各自独立核对关系，不相互套用公司。目录恢复后的未知附件身份也能沿原身份接续继续，不重写旧正文或模型输出。

同一附件版本的任务已经运行、取消或耗尽重试时不重新建立相同任务；附件撤回、来源修订、人工修改、共享额度、暂停和恢复锁继续约束自动操作。每份附件分别消耗身份核对额度，关联后可能增加研判调用，均计入原总额度。一次核对最多30项提及，输入保留原512KiB上限，未识别不代表没有相关公司；只覆盖当前明确链接且已经可用的附件，不扩大为全网搜索或母子公司知识图谱。

在现有“深入研究 → 证据 → 来源与模型候选”的身份记录中，可展开“与原事项的关系”，查看关系理由及原事项引用；附件引用保留在上方。首页五区、主导航和最终决定不变。该功能已在隔离合成流程验证，真实附件选择、公司关系、业务敞口、行动判断及模型成本/时效仍需独立核验。

### 目录状态读取的性能与完整性

状态刷新不应反复解析全部目录。新候选增加按市场查找目录的索引，并复用已校验的只读目录及有限名称召回结果。内部目录递归冻结；公开读取仍返回独立副本，不能从一个页面读取结果改坏后续身份判断。目录缓存最多8项/32MiB，召回结果最多128项/8MiB，超出上限不缓存；复用现有SQLite变更检查，任何本连接写入、其他连接提交或schema变化均使缓存失效，事务内完全绕过缓存。目录依据的可用时间每次先核对，跨日和同日时钟回退不能误用未来快照。

在包含美股、沪深和港股历史目录的同一公开批次副本上，以相同配置和固定时间分别重复三轮，后台状态中位数从4.087秒降至0.713秒，首页汇总从10.279秒降至5.211秒。业务和状态内容逐项一致，仅源码版本指纹按新程序改变。此为单机、单批静态副本测量；首次读取仍较慢，活动研究的数据库写入会使缓存失效，不能据此宣称分钟级全量处理或千篇吞吐已经达标。旧研究、模型输入、证券选择规则和账户政策不变。

### 已核验材料的状态读取

看板和运行详情会多次读取同一份保存的研究依据。现在按数据库连接、材料ID和修订号复用已完成完整性核验的材料，减少申报HTML等原件的重复解析。沿用现有SQLite变更检查：本连接写入、其他连接提交、schema变化均失效，事务内不使用或填充缓存；每次对外返回独立副本，不能由调用者修改缓存。每个连接最多128项、32MiB；超过大小上限的单项正常核验但不缓存，数据库连接可回收后不保留全局引用。

缓存只表示本次未变化数据库上的材料完整性。现行材料比较仍独立查询最新修订，不能把旧材料变成当前依据；原件缺失或损坏、材料正文改动、回滚和跨连接状态变化仍沿原规则拒绝。材料内容、来源、当时可用时间、模型输入和旧研究不回写。这不证明原文事实可靠、研究质量或可交易性。实际性能和验证范围见任务清单与本轮交付记录。

### 阶段轮流调度

自动研究的一个来源可能拆出多项内容。原队列按所有任务的入队顺序推进，容易把额度先用在整批身份识别上，已具备身份结果的事项仍等不到研判。本地候选在原事件任务内轮流处理“事项识别 → 公司身份 → 研判”，空阶段跳过，同阶段保持先入先出。行情和财务准备仍逐项执行，完成一步后也让其他阶段继续；各来源、比较、归组及综合沿用外层的原轮流调度。

下一阶段持久保存；重启保持顺序，暂停、模型占用和额度等待不会消耗阶段。启动模型与指针、尝试记录和租约原子提交，失败按原次数和退避处理。已完成结果仍可在额度耗尽后保存。这里没有调整账户政策、每日默认额度或模型配置，不把多事项都视为重大事件，也不省略公司、价量和财务核验。

首页、操作入口和运行详情沿用原结构；用户启动后台后无需决定阶段顺序。历史人工模式保持原队列，已完成研究及旧输入不改写。实际性能及质量证据见[任务清单](BACKLOG.md)，调度回归通过不等于分钟级时效或独立研究质量通过。

阶段交替也可能使某项研判早于其他事项的识别。后来完成的事项会对仍未变化的早期系统研判补查反向词项线索，加入本次新的比较范围；原先冻结的召回记录保持。该线索仍需原模型比较及完整配对，不根据词项直接合并事件，本人修改或归档的旧研究不由这条补充路径接续。


## 引用完整性与纠错留档

新包用research-output-contract/2发送原短引用编号和引文边界。引用编号是q加1至6位不以0开头的数字；引用表内唯一，各citations数组内部不重复。表内所有编号必须恰好属于实际使用集合；五章的sourceIds和文字提到材料不算使用短编号。先确定每个判断所需的真实引文，再构成引用表，不为用完编号给无关判断添加引用。原字段、原引用语境与还原后校验保持。

自动重试新增research-output-feedback/3。程序先核对原输出哈希、支持的引用协议、材料身份/修订和逐字原文，才报告编号格式、重复编号、缺失引用、混合对象、单处重复或未用引文的受控位置；只回送合法短编号、索引与规则，不回送任意旧回答或对象键。引用还不能展开时，可以合并独立的财务格式问题，不能因此把数值引用视为通过。无法安全诊断时继续原失败策略；本项不是覆盖所有语义或格式错误的通用修复器。

后台按原材料重新生成全部研究，不编辑原输出，不在服务端自动删除未使用引用。旧/1和无标记包仍沿原契约，可在原有效重试中使用新反馈；额度、三次上限、退避、暂停、取消和恢复锁保持。达到上限的旧事项保留观察，其他研究继续，不因程序升级清空次数。

新前向记录在调用开始前冻结实际带反馈的提示、schema及反馈指纹，并绑定前次失败运行；完成后逐项核对，修改这些来源或轨迹不能仍显示一致。重试仍明确排除独立首轮样本，历史档案按当时记录读取，不回写旧指纹。输入有效、执行一致、引用通过、独立语义质量和收益效果分别验收。当前真实验证及授权边界见[任务清单](BACKLOG.md)。


## 公开来源跳转后的附件接续

发布方可能将原通知中的附件地址跳转到新的文章路径或文件主机。读取器原已逐跳验证公开HTTPS和DNS，但归档只保留最终地址，原通知按原地址查找会把已读附件误留在未读状态。本地候选在现有读取日志中保存原请求、最终地址及材料版本；归档和日志原子提交，不改变材料正文、内容指纹或历史输入。

明确附件自动接回时，除原请求、来源链和当前版本核对外，还要核对该来源主题或其正文入口条目的成功读取记录。直接地址沿原规则；新跳转可据此接续。缺少记录的旧跳转、人工粘贴内容、失败读取及其他任务的记录不能替代。本来就是普通网页引用的内容仍需独立研究与事项比较，不按链接关系强行合并事件。

实际公开来源读取、离线响应回放与合成流程测试分开记录。实际读取成功只证明当次可提取正文，不证明网页全文完整、事实、公司敞口或买卖建议成立。已耗尽的读取或模型任务不会因本修复清空次数；正式实例、账户和交易不随本地候选改变。

## 持仓触发自动更新研究

原自动研究任务开启时，后台轮流检查仍持有证券的当前单事项系统研判。复核期限到达，或者观察任务已核对的退出、失效、下次检查条件命中，都会自动追加新版研究队列。价格准备开启时重读日线及分钟资料，旧价格、旧判断和原持仓记录保留。运行日志显示持仓证券及“持仓条件或期限触发，后台更新研判”，可沿原详情进入研究，不需人工处理中间步骤。

条件检查必须当前有效且在两分钟内；缺数据、暂停或旧检查不触发。持续命中同一定义不会重复调用，只有一次已核验的不命中之后再次命中才重新触发；原绝对期限只消费一次。队列和触发状态持久保存，额度耗尽时等待，原失败次数与退避不变。读取中清仓或人工修改会阻止保存或启动后续调用。

本路径接续自动生成的单事项研判。它不直接处理人工研究或事件综合，也不改变本人最后买卖决定和观察范围设置。模型只取得证券与研究依据，不传账户、数量或成本。历史触发与新材料各自保留时点，缺证据仍应输出未知；完整质量和真实市场验收见任务清单。


### 综合事件的持仓复核

多个事项汇成系统事件后，其当前综合判断同样参与持仓期限和条件复核。后台为同一事件追加新综合版本，成员研究、原综合与账户保持。价格准备开启时在本次综合内逐证券读取日线和分钟材料，原件、失败、次数和下次时间保留；三次读取失败后明确带缺口继续研判，不编造当前价格。

新版排队、取消、失败或无法核对期间，旧综合不会被重新标为当前有效。完成后，新输入、触发依据和模型输出绑定同一版本；来源、成员、配置变化及清仓会阻止在途任务保存。关闭自动、暂停、原滚动额度及最后本人交易决定保持。

综合模式下，原后台日志的“当前研究”筛选该事件的记录，查看对应记录进入具体综合版本；可在原详情阅读成员、依据和历史。日志归属来自已保存任务，与自由文本独立。直接人工研究不因此自动接管，真实三市场、多账户与质量/时效仍按任务清单验收。


## 持仓与关注表的行情范围

关注表之外的持仓行情沿原事件日线图和公司研究详情显示，行情能力说明使用同一缓存及来源时间。可见关注池仍只有本人关注的最多40项；不把后台持仓加入该列表。已手动移除的持仓可查看已有历史缓存，移除不代表删除价格历史，也不会由查看动作重新启用采集。

研究模式的非零实际记录和两个市场模拟账户持仓，自动并入原日线与分钟任务；同证券跨账户只采集一次。可见关注表仍最多40项，满额不会再让持仓永久等候添加。每轮日线和分钟各最多处理40个证券、分别3和2并发；先从持仓开始，随后持久游标轮流覆盖整个范围。证券数超过单轮容量时需要后续周期，不保证所有持仓每分钟都有新行情；每个证券原来源/备用请求、缓存、冷却、价格有效性检查保持。

手动移除证券会保存停用意图，新研究或新账户不会强制加回。旧版本已登记但不在关注表的关系继续按人工移除处理。本人明确重新关注后恢复；暂停任务、恢复核对锁和清仓均优先。清仓但仍保留关注的证券继续采集，历史行情及账户事实不删除。读取中退出范围会阻止后续备用请求和晚到缓存保存。

原持仓详情、监控检查及运行记录反映范围和实际缺口，查看不启动请求；不增加日常中间操作。此处取得的是研究行情，可支持原结构化价格条件，不能绕过合格执行输入去计算可执行买卖、账户当前收益或模拟成交。首次安装及来源配置的真实可用性仍须独立核验。

## 持仓消息的后台优先复核

研究模式以非零实际记录和两个市场模拟账户的证券/原研究引用计算新闻优先级。原事件详情说明涉及持仓及风险线索，关闭持仓后等级随之重新计算；普通关注不等于持仓。现有标题、有限实体及来源/研究关系用于召回，识别不到时不能保证优先，不能把重大性未评的线索解释为买卖建议。

自动研究已入选的queued/ready正文准备先取已识别持仓风险，连续三次后处理最早等待项，轮转跨重启保留。当前新闻修订有索引时使用该版本，无当前索引时使用任务冻结初筛；原任务记录保存选择原因与时间，查看仍只读。暂停、原额度及模型租约优先，准备记录写入失败不会发起读取或推进轮转。

本规则不改变未入选正文初筛、身份、研判和综合的原阶段轮流，不保证完整新闻全集或所有阶段的固定延迟。首次恢复副本需沿原流程核对后由正常后台周期建立内存事件索引；核对前空索引不证明原材料已删除。真实覆盖、研究质量及发布状态统一见任务清单。

## 单篇来源修订后的持仓接续

原持仓若基于单份自动研究，新版报道完成全部事项研判后，后台比较原文旧版所有事项和新版所有事项。完整且唯一对应后自动跟踪当前研究；没有事件簇也能继续。比较仍共用原24小时额度及三次尝试，失败限次后保留观察；暂停、取消、恢复核对锁及本人编辑保持优先。未知或多种可能不会被强行配对，也不要求本人为每条材料处理中间审批。

对应关系与比较批次持久保留；旧材料、研究、建仓版本和成本保持。读取当前持仓时重新核对对应及研究是否有效，新修订或撤销依据会使旧卖出方案失效，已成交部分仍保留。当前事项后来归入有效事件簇时，监控接续事件综合；没有合格新判断期间保留原持仓与价格风险。

### 首版确认记录的升级与回退边界

实际记录沿用原身份和保存内容；新增手动模拟使用独立身份命名空间，共用逐笔核算与净值采样。运行早于RC-D210的程序时，不应直接读取已经新增手动模拟记录的数据库；旧程序不理解该身份。回退使用升级前备份与其对应程序，保留升级后数据库供恢复，不能将新库覆盖到旧程序并宣称兼容。本次隔离测试验证新程序重开同库及两类账户隔离，未修改正式数据库。
