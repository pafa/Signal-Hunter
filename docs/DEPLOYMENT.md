# 本机生产运行与恢复

本批补齐运行基础，仍只监听 `127.0.0.1`。没有远程身份认证，不要直接公开端口。数据仅用于研究与结构演练，尚无市场模拟执行或自动模型研判。

## 安装与运行

在项目的 `prototype` 目录执行：

```sh
npm ci --ignore-scripts
npm test
npm run build
npm run start:production
```

默认使用独立 demo 库和生产静态文件，网页与 API 同源使用 4178 端口；不启动 Vite 开发服务器。原有 `npm start` 开发入口继续保留，使用 4178/4179 双端口。检查生产入口：

```sh
npm run health -- --production
```

空白研究模式：

```sh
npm run start:production -- research
```

原数据库切换前必须先备份并在副本验证；不要把演示库改名为研究库。运行器不自动载入 .env；环境变量沿用 SIGNAL_MODE、SIGNAL_DB_PATH、SIGNAL_FRONTEND_PORT 和 SIGNAL_API_PORT。生产模式只有网页端口监听；健康状态、版本与任务记录来自同一实例。

前台运行器会恢复意外退出的 API 子进程，最多 5 次并逐次退避；超限退出，避免故障重启风暴。它不能替代开机服务管理器。关闭浏览器不会停止任务；关闭终端或注销是否持续运行由系统服务管理器决定。

## 后台服务配置

生成配置不会安装、启用或修改系统设置。先确认路径、模式、数据库和端口，审阅具体候选后再启用。macOS 使用用户登录服务，Linux 使用用户 systemd；尚未完成 Windows 服务支持。

```sh
npm run service:config -- macos ./signal-hunter.plist demo
npm run service:config -- linux ./signal-hunter.service demo
```

命令拒绝覆盖已有配置。配置包含当前 Node、源码和数据库的绝对路径，属于本机生成物，勿纳入源码发布。长期目录应固定，移动后重新生成。macOS 配置不保证注销后或机器睡眠时继续运行；Linux 注销后的运行也依赖用户服务设置。

macOS 在核对候选后，可使用 launchctl bootstrap gui/<用户数字ID> <配置绝对路径>；停止用 bootout 指定同一服务。Linux 在核对后把文件放入用户 systemd 配置目录，执行 daemon-reload 后启用。安装和真实主机重启验收是独立步骤，本批未替用户启用服务。

## 运行控制

主屏“查看状态”打开运行控制台。新闻、日线、分钟、本地备份分别显示暂停状态、开始/完成时间、最近成功、下次检查、错误及最近 50 次运行记录。

- 暂停：阻止后续运行，取消本进程中的采集请求；已提交的数据保留。
- 恢复：保留历史，重新安排该任务。恢复不批准交易。
- 重新检查：人工安排下一次执行；仍遵守来源冷却、暂停与数据库互斥。
- 连续全部失败达到 3 次：等待人工处理后重试；部分源失败保留成功结果，其他来源和任务继续。
- 中断恢复：持久租约到期后恢复任务；旧执行者失去租约后不得再提交采集结果。

手动新闻、日线和分钟刷新也登记任务输入与结果。运行器每 10 秒检查到期任务；新闻默认 10 分钟、分钟默认 1 分钟检查，日线沿用交易日和缓存规则。检查频率不等于上游实时更新频率。

当前只给已有三路采集和备份接入持久任务；后续研判、条件检查和市场执行接入时须实现自己的幂等校验，不能仅靠任务租约防止重复成交。

## 一致备份与恢复

运行实例每小时自动备份到当前数据库同级 `backups` 目录；第一轮启动也会检查是否到期。备份包含 SQLite 中的研究、材料、新闻、行情、账本、任务与控制状态，不包含环境凭据、操作系统服务配置或数据库之外的文件。每份备份附模式、表计数、完整性检查和 SHA-256。数据库备份采用 Node 的 SQLite 在线备份机制。

手动备份示例（仍在 prototype 目录）：

```sh
npm run backup -- create ../data/runtime/research.sqlite ../data/runtime/backups
npm run backup -- restore ../data/runtime/backups/snapshot-示例 ../data/runtime/restored.sqlite
```

恢复只允许全新路径；拒绝覆盖已有库以及存在 WAL/SHM 的目标。校验指纹和完整性后复制；采集任务全部暂停、运行中的任务标记中断。用正确模式打开恢复副本，核对研究、持仓与申请，点击“已核对恢复数据”，再分别恢复需要的任务。确认本身不会恢复任务。

所有备份暂时保留，不自动删除；需定期检查磁盘容量。保留周期、磁盘满只读模式及异地主机备份属于后续工作，不能把本机快照当作异地灾备。不要在运行中只拷贝 SQLite 主文件，遗漏 WAL 可能丢失记录。

## 诊断与降级

证券能力表分别展示日线与分钟来源、最新数据时间、接收时间和错误。日线获取成功不代表分钟可用，也不能证明具备可成交报价。当前执行能力始终标为研究观察。

- 上游 403：记录来源拒绝，保留缓存；不绕过权限或自动改用付费源。
- 来源超时：独立失败及有限重试；不能把失败显示成“没有新闻”。
- 服务存活与来源成功分开：健康接口只证明本机服务与数据库可读，不承诺上游正常。
- 任务“已完成”只表示一次执行结果，不能替代长期稳定性或识别准确率。

## 本批验证范围

本机 Node 24、macOS；临时合成库完成单元与 HTTP 集成验证。独立进程崩溃恢复约 1.4 秒，暂停和场景账本不变，端口冲突保留原服务。桌面 1440×900 与窄屏 390×844 检查运行控制及刷新后的暂停保留。

尚未安装系统常驻服务、验收真实主机重启或连续 14 天运行；Linux/Windows 未实机验证。行情权限、完整模拟执行、远程认证与自动模型仍未交付。本批不修改个人原目录、原库或已发布版本。

技术依据：[Node SQLite backup](https://nodejs.org/docs/latest-v24.x/api/sqlite.html#sqlitebackupsourceDb-path-options)、[Vite 部署说明](https://vite.dev/guide/static-deploy.html)。


## 免费源诊断与请求冷却

2026-10-01 对 A/H/US 各一个证券独立诊断：主源连接中断，备用源返回 HTTP 403。该抽查不能代表全部证券；本批未恢复分钟数据，也未尝试绕过拒绝。

新增来源级持久冷却：403/429 暂停该主机请求 30 分钟；连接错误/5xx 从 1 分钟逐次退避至最多 15 分钟。重启或手动刷新不绕过冷却；不同主机状态分开。工作台列出来源错误和可再次请求的时间。成功取得部分报价仍不能证明具备市场模拟执行能力。

## 有界真实行情核验

在prototype中运行：

```sh
mkdir -p ../session-artifacts
npm run market:verify -- ../session-artifacts/market-check-01 600519.SH 00700.HK AAPL.US
```

输出目录必须是全新路径且父目录已存在；已有目录会在请求前拒绝，最多12个指定证券。命令使用全新内存研究库，调用工作台相同的日线/分钟适配器、身份检查和来源冷却；不接受个人数据库路径，不触发后台调度或订单。403/429等冷却在本次运行内共享；命令没有自动重试，不应循环运行以绕过来源限流。

report.json保存来源请求结果、实际时点、缓存诊断、执行边界和账本不变；normalized-data.json保留规范化返回数据，其JSON紧凑序列化SHA-256写入报告。文件只在本地，需遵守供应商数据权限，不随源码发布。请求全部成功返回0，存在来源失败返回2，输入/保存错误返回1。退出0不证明实时、完整覆盖或可成交；检查具体数据状态和时区，美股未知主源时区仍不推断。

已知UTC及A/H适配器标明的UTC+8时间用于诊断。未明确时区、无效日期和未知市场日历继续显式展示；当前分钟末条可能不完整，盘中数据仍是研究参考。


## 本机 Codex 研判候选

当前模型入口使用已安装、已登录的 Codex CLI。调用会把当前事件的材料发送给 Codex 使用的模型服务，使用当前账号能力与额度；“本机入口”不是离线推理。不安装独立本地模型，也不读取或复制凭据。独立本地模型留待正式部署时评估。

研究实例启动前明确配置下列环境变量（运行器不自动读取 `.env`）：

- `SIGNAL_CODEX_BIN`：已安装 Codex 可执行文件的绝对路径，不接受任意 shell 命令。
- `SIGNAL_CODEX_MODEL`：该账号可用且明确选定的 Codex 模型名称。本轮实测使用 `gpt-6-astra`。
- `SIGNAL_CODEX_EFFORT`：推理强度，默认 `high`；需与所选模型兼容。
- `SIGNAL_CODEX_TIMEOUT_MS`：单次研判超时，默认 180000，最大 600000 毫秒。

配置后按已有方式启动独立研究实例。在“研究详情 → 材料与研究”点击“使用 Codex 生成候选”。生成前冻结研究版本、完整输入和指纹；运行记录保存在当前数据库的 `model_research_runs` 中。列表只显示最近 50 次，旧记录仍保留在数据库中。任务失败或取消保留记录，服务中断后的过期任务可手动重试，不自动重复调用。一个数据库同一时刻只允许一份模型研判。离线演示即使提供配置也不会调用模型。

生成结果通过既有章节和引用校验后显示为“待复核候选”。本人点击“采纳为研判草稿”才保存研究新版本；旧版本保留，模型来源随手工编辑继续保留。采纳不等于完成核对，也不会创建、批准或执行订单。研究或材料已变化时拒绝采纳旧候选，须重新生成。结构和引用存在性校验不能证明结论正确，仍需复核事实、反证、量级与未知事项。

调用使用独立临时目录、只读沙箱、临时会话和明确模型配置，不继承桌面任务的工具管道或自定义模型配置。shell、插件、应用、浏览器、网络搜索等相关工具选项关闭，并在运行事件中发现工具活动时终止并拒收候选。当前实测 CLI 仍会声明部分工具，并产生 code-mode host 关闭的运行警告；不能据此宣称运行时完全没有工具。临时运行文件会清理，原始提示词可由输入、提示词版本及代码恢复，候选保留原始模型 JSON、模型/CLI/提示词/Schema 版本指纹及用量；原始 CLI 日志不进入页面。

输入超过 512 KB 时明确拒绝，不静默截断。默认三分钟超时不保证所有材料都能完成；真实合成样本耗时约 145 秒。大材料分层处理、更多真实样本质量与长期运行仍需验收。

如需离线整理材料后单独调用，也可使用已导出的标准研判材料包：

```sh
cd prototype
npm run research:codex -- /path/to/packet.json /path/to/new-output-directory
```

须先配置上述环境变量。输出目录必须不存在，父目录必须存在；命令保留 `input.json` 及 `candidate.json` 或 `failure.json`，只写本次全新目录，不打开研究数据库。此命令的候选不会自动导入页面；页面内发起的候选才进入上述采纳流程。材料、生成结果与数据库都属于本地研究资产，不进入 Git 或公开发行包。

## 固定已有研究入口

默认数据库路径相对于当前源码副本。换 checkout 或工作树后运行 `npm start`，会打开该副本的演示库；它不会自动找到原研究库。已有研究应只读登记一个固定入口，放在源码目录之外：

```sh
npm run instance:create -- /absolute/data/research.sqlite /absolute/config/research.instance.json '我的研究' 4178 4179
npm run build
npm run start:instance -- /absolute/config/research.instance.json
```

登记要求已存在、已标记模式且有历史版本的数据库；不会初始化、迁移或覆盖数据库/配置。配置以绝对路径绑定数据库、模式、端口和最早研究历史的 SHA-256；无研究时采用初始账本历史。启动时在 schema 初始化之前，只读验证模式与该历史版本。文件丢失、锚定历史缺失或指纹不符时停止，禁止默默新建空库。后续合法新版本保留旧历史，因此不改变身份。该核对用于识别数据集，不是完整性校验或迁移验收；从同一历史复制出的库仍需人工核对路径与用途。

配置可跨源码工作树复用；生产静态入口固定使用配置端口。环境变量 `SIGNAL_INSTANCE_PROFILE` 也可指定同一绝对配置路径；与模式、数据路径、端口或静态入口冲突的环境设置会报错。配置文件含本机路径，权限为0600，`*.instance.json` 被 Git 忽略，不在发布允许清单内。不要手改配置来绕过历史核对。切换候选代码仍须先备份、在副本验证兼容性，并完成具体版本的部署审阅；固定入口本身不会批准升级。

页面顶端显示数据集名称、模式、主题数、文件名和身份短码。未登记的入口明确标为“入口尚未固定”。固定实例提供的身份以配置为准；未固定入口只按数据库路径区分，不能识别同路径文件被替换。API 的 `/api/health` 与 `/api/data` 提供身份，但不暴露绝对路径。浏览器绑定首次读取的数据集，编辑请求携带 `X-Signal-Instance`；若同一端口换库，旧页面的请求被拒绝，需要刷新并核对数据后继续。脚本调用变更接口也必须先读健康状态，再携带其 `instance.id`。

生成系统服务模板时可设置 `SIGNAL_INSTANCE_PROFILE`，模板会保留固定入口并采用独立服务名；仍只生成，不自动安装。配置和系统服务文件需要另行备份，SQLite 快照不包含它们。私人数据继续保存在 SQLite：新闻修订、研究历史、材料及模拟记录与代码 Git/PR 分离；代码切换不意味着数据应被删除或重新采集。
