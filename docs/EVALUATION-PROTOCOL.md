# 前向研究评估协议 0.3

本轮冻结研究基线；冻结脚本保留持久研究配置，但不采集模型进程环境，不能据此声称已冻结全部实际模型调用配置。不宣布模型有效，不启动自动优化或真实价格成交。既有结构演练账户、回溯案例、附件研判和 9 月 10–24 日测试批次均为开发材料。

## 固定与留出

- 使用 `prototype/scripts/freeze-evaluation.mjs`，以只读事务截取当前研究、历史、正文材料/读取记录、新闻修订及初筛，保存 server/shared 全部规则与本地依赖、依赖锁、当时配置和 SHA-256；输出到被 Git 忽略的 `data/runtime/evaluation/`，按日期、package.json版本和前向协议版本命名，重复执行不覆盖。已冻结的 `baseline-20260925-v09.json` 保留；v0.10 与以后规则独立冻结，不将新版结果混入旧版。v0.8 因遗漏 event-routing 等实际依赖，不再作为完整重放基线；文件保留并由 v0.9 指明替代关系。
- 新时间窗口从北京时间 2026-09-26 00:00 开始，并且不得早于实际冻结时刻。新事件需记录真实首次获取时刻、输入可用时刻、判断时刻、原始输入哈希和规则指纹。缺少任一项只入探索档案。所有日期必须有效且有时区，首次获取 ≤ 本版可用 ≤ 判断，冻结 ≤ 前向起点 ≤ 首次获取。
- 已有主题及其后续发展、同一交易/产品/政策/事故的报道归属同一事件簇。新 ID、新文章或跨市场股票不等于新事件。人工在判断前冻结簇身份；不确定关系标为待定，不纳入独立验证。
- 0.3基线冻结全部活跃/归档事件簇、所有成员历史和当前索引，不限于界面最近记录；同时保存已见研究/历史ID、新闻ID及正文documentId的排除清单。新闻修订、正文修订、事项重新拆分和换新簇ID不产生新样本资格；同一旧正文中的新事项保守地留在探索档案。簇表不完整、快照指纹/历史版本/成员索引不一致时拒绝冻结，不输出不完整清单。
- 前向记录必须附上判断前核验的完整 `clusterMembers`，逐项保留kind、id、revision；material和event另带documentId。缺成员、缺稳定身份、重复成员或命中任一已见来源均拒绝。此函数只校验传入记录，不能独立证明调用者给出的成员覆盖完整或归簇语义正确；服务端登记现绑定不可变成员快照，归簇语义仍须独立复核。
- `forwardEligibility` 执行准入；留出标注不参与调参。旧0.2档案不重写，缺少成员排除清单时不能按0.3放行。候选调参必须形成新版本，使用之后的新窗口及新事件簇验证，不能改写本次基线。
- 服务端可以登记五章研判调用前的输入，但当前尚未自动生成独立合格前向样本。开发候选的簇确认发生在语义模型比较之后；即使早于五章研判，也不能当作独立标签或盲审，不自动进入评估真值。全库自动事件识别仍待完成。

## 标注与档案

重大性标签：重大 / 普通 / 不明确。重大需写出信息增量、影响规模、持续性、财务传导及反证；仅标题含热点词不足。公司关系单列直接、上下游、竞争、同业联动、待核验，不能把同业上涨当盈利证据。

命题、类型和截止日固定后，变更这三项必须新建独立主张；不能沿用旧首次概率评价新问题。结局日期无效、处于未来或早于首次概率判断时刻的记录不得作为成熟结局。

每个主张分别保留事实状态、主观概率、评估时刻、检验日、成立/不成立影响、证据 ID、修订原因及结局。结局为兑现 / 未兑现 / 部分兑现 / 未解决 / 跟踪中。部分兑现和未解决不得强填 0 或 1；未校准概率不得称胜率。

评估档案每条保留 `topicId, clusterId, clusterReviewedAt, clusterMembers, origin, firstSeen, availableAt, decisionAt, inputHash, rulesHash, label, labelReason, reviewer, reviewedAt`。拒绝、失效、未成交、亏损、无信号、误报和漏报均保留，不能只选成功案例。漏报通过独立来源抽样发现并加入档案；当前没有完整真值集，不能报告总体召回率。

## 指标与有效性边界

1. 研究阶段：覆盖率、公司映射准确性、事实与推论分离、反证覆盖、来源可追溯率；同时报告样本数、缺失及标签争议。
2. 概率阶段：仅对有明确二元结局的冻结预测计算 Brier 等指标；按事件簇分组，避免多条转载或多个主张当独立样本。首次概率与修订概率分开。未解决和部分兑现单列，不静默删除。
3. 交易阶段：以后分别计算事件后价格变化、实际模拟成交收益、组合净值；须先确定真实 FX、费用、滑点、交易日/停牌/涨跌停/可卖数量、未成交处理、基准和持有期。当前场景收益不纳入。

样本不足、结局未成熟、输入时间未知、跨期信息泄漏或已见事件簇均需报告原因，不能以短期上涨证明规则有效。本协议包含准入、结局分类与下述回溯诊断指标；真正独立的前向样本和长期结局仍需按本协议积累与验收。


## v0.11 初筛样本入口

`screening_samples` 保存所有层级的标题输入、新闻修订实际可用时间、判断时间、输入指纹、初筛结果与规则指纹；`screening_rules` 保存当时完整初筛依赖文本。重复运行不覆盖旧输入。同一新闻修订后的内容单独留样。

早于该规则启用的首次入库材料记为历史诊断；启用后首次入库单独记为 prospective-intake，但不是本协议的合格 forward-capture。当前没有事件簇排除审查、独立标签或效果统计，因此全部样本 `evaluationEligible=false`。初筛依赖指纹不等同于完整评估基线 `rulesHash`；后续转换需冻结完整基线并重新检查本协议条件，不能直接把两者混用。

人工复核分重大候选、普通资讯、信息不足，保存新增量、相对规模、公司传导、预期差、期限和理由。用户已看到规则结果，故记为非盲审；该标签是研究复核资料，不是独立验证真值，也不将信息不足算作负例。新闻样本数量不等于独立事件数量。


## 冻结批次、隐藏规则标注与描述统计

从“研究评估”建立批次，选择初筛规则指纹和判断时间窗口。窗口为 `[start, end)`，包含该规则在此窗口内保存的全部初筛层级与新闻修订；不接受从浏览器提交自选样本或自制预测。超过 5000 条拒绝创建并要求缩短窗口，不静默截断。数据在同一 SQLite 事务内冻结；后续新闻修订、研究变化与重新初筛不会改写批次。

冻结内容包括标题输入及原始可用时间、当时规则结果、完整初筛规则文本、当前 server/shared 源码及依赖锁、评估协议，以及冻结时刻之前的全部研究主张历史。标题样本只限选定窗口，主张统计则覆盖冻结时的全部研究，两者在界面中明确分开。输入、来源和最终报告各自保存 SHA-256，导出可复核；哈希不防拥有本地数据库写权限者重造整个档案。

封存前，批次详情接口与界面不提供初筛结果、完整规则文本或评分。人工对每条标题标注重大候选 / 普通资讯 / 信息不足、事件簇、评审者、依据和是否此前见过规则结果；重大候选还需新增量、相对规模和公司传导。信息不足也必须留记录，事件簇不明可留空。“此前未见”只是评审者自述；单用户工作台其他入口可能展示过结果，隐藏当前界面不能证明真正独立或盲审。

全部标注完成后，本人显式封存并揭示结果。封存前修改标签生成新版本；封存后原批次不能改写，纠错须另建批次并保留旧报告。重试相同命令幂等，旧版本写入拒绝；恢复副本仍需先通过恢复核对。浏览器草稿按数据集、批次和样本隔离，草稿不替代数据库保存。

### 初筛指标

- 规则 `review` 为阳性，`quiet` / `clue` 为阴性；未知规则结果不当阴性。人工重大为阳性、普通为阴性，信息不足与未标注排除出二元分母，但数量始终列出。
- 同时报告逐条标题的 TP/FP/FN/TN、精确率及**本样本集内**的召回率。分母为零显示不可计算，不显示 0%。没有独立来源真值集，不可外推到所有新闻。
- 事件簇口径只取每簇判断最早的样本；同一时刻按样本 ID 确定。代表选择不看标签或成败，代表标签不明时该簇不进入二元指标；后续修订数量、未知簇和未评分簇另列。这种归组是人工诊断口径，不能证明事件真正独立。

### 概率指标

主张身份（内容、类型、截止日）必须跨版本一致，二元结局需有效时间、理由和结局证据引用；证据获取时间必须不晚于人工结局登记。部分兑现、未解决、缺时间或缺证据不填 0/1。

首次记录概率与人工首次登记结局之前的最后概率分别评分。首次为空不回填后续概率；结局登记时改为 100% 不算预测。曾登记兑现/未兑现/部分兑现再重开后，后续概率不回流成事前预测。只有两种概率都有效的同一批主张才进入配对比较。保留每条纳入/排除记录，以及事实、兑现、盈利、价格主张的分组统计。

Brier 为 `mean((probability / 100 - binaryOutcome)^2)`；分别列出样本数与 5 个固定概率箱（左闭右开，最后一个包含 100%）。分箱和 Brier 都是描述统计：主张可能相关、概率是主观判断，人工结局登记不等于已核验的事件发生时点。因此报告始终 `forwardEligible=false`，不将回溯窗口转换成前向有效性证据，不自动调参或晋升模型。

原初筛评估报告不内嵌信号后价格或市场模拟收益。封存后可另建下述独立价格窗口报告，旧报告原文不改写；经核验的市场基准、真实执行适配器与长期样本仍待验收，不以场景账本或短期上涨替代。完整前向标签与结局登记、独立审阅人/来源真值、实际事件时点核验、基线与候选在未参与调参窗口的比较、长期收益归因仍是第 16 项剩余要求。

## 官方历史材料的语义诊断

有限历史案例可以检查事件身份、阶段与引用，但不满足上述前向资格。调用前冻结来源URL、当前获取时间、未改写的提取正文、材料修订、所有配对、参考标签、评分口径、提示词/schema、模型配置及代码快照。标签若由研究助手阅读来源形成，须明确记为助手参考，不能称为独立人工真值或盲审。

使用已有来源读取、材料保存、成对比较和持久模型记录流程；不另写模型提示词或为通过测试缩写正文。来源提取失败、模型失败、无法判断都保留；不看到结果后删样本、改参考标签或自动重试。后来发现参考错误时保留旧版，并建立另一次明确说明原因的诊断。

事件身份主口径：repeat/followup/reversal表示候选同一事件，related/analogy/unrelated表示未归为同一事件，uncertain单列为弃权。这是有限诊断的操作性分组，不表示related已经证明客观上属于不同事件。阶段类别另按预先声明的可接受集合核对，未知及失败不进入成功分子。逐字引用检查仅证明引用存在，仍须逐项阅读主体、对象、阶段和时间是否得到输入支持。

逐对结果必须同时给出独立事件家族数，复用材料的配对不能视为相互独立样本。著名历史事件可能已在模型训练资料中，英文公司公告也不能代表A/H中文新闻、传闻、多事件长文或日常分布。无论结果如何均保持`forwardEligible=false`，不据此计算全市场准确率、晋升模型、自动合并或启动交易。

公开审阅只包含来源链接、日期、指纹、预先声明的口径和各次结果元数据；第三方正文及带原文引用的模型输出只在本地评估档案留存。原始读取结果、输入、运行记录和代码快照用文件清单及SHA-256核验，版本升级不覆盖旧档案。首轮清单见[官方材料语义诊断](evaluations/semantic-official-20261003.json)，执行状态仍以[任务清单](BACKLOG.md)为准。

## 服务端前向调用登记

在“研究评估 → 前向调用档案”显式冻结新基线后，后续手动和自动五章研判共享同一登记钩子。冻结本身不调用模型；默认不启用，可以暂停新登记。新基线不会改写旧基线，重试相同请求返回原记录，不会重新启用已暂停或被替代的基线。恢复副本核对前拒绝冻结和模型调用。

基线保留本协议0.3的全部排除档案，并保存服务端指定的本机Codex路径、模型、推理强度、超时、提示词版本和schema指纹；不保存凭据或继承的进程环境，也不以二进制路径证明程序内容不变。冻结核对当前源码与模块加载时指纹，文件在运行中变化时需重启候选服务后重新冻结。现有基线发生代码或模型配置变化时，后续记录保留但标为排除。

模型run、材料包指纹、研究版本、输入指纹、事件簇当前完整成员快照、来源获取/可用时间、规则与执行依据，以及自动队列关联/租约在同一写事务登记；任何存储失败全部回滚，模型尚未调用。客户端只提交基线名称和请求标识，不能自填成员、首次获取时间或模型参数。原模型run保留完整材料包和结果，前向档案通过指纹绑定读取；后续编辑、归档、模型采纳、暂停及基线切换不重算旧登记。

每次五章研判都留记录，输入准入只检查可证明的结构条件。未完整绑定单一有效簇、来源时间无法核实、旧来源对照、研究已调用过、代码/模型变化均保留具体原因。同一簇或任一稳定来源已在之前的前向调用中出现时，后续研究ID、簇ID或来源修订不能再次计为新输入；首次失败和排除记录也参与去重，不按成功与否挑选。

查询重新核对基线/档案指纹、完整材料包、模型run、原始输出和实际执行trace。输入准入、档案关联完整性和实际执行依据分别展示；失败或未完成调用可能没有完整trace，不自动解释为模型成功。所有登记仍为 `forwardEligible=false`，尚无独立标签、结局和效果验收。记录覆盖五章研判，不代表拆分、语义比较、身份识别的独立评估。

基线和调用档案进入SQLite备份；页面展示最近50个基线及100次调用并同时给出总数，旧记录不删除，可按ID读取。指纹用于发现意外不一致，不防具有数据库写权限的人重造整个档案。标签、实际事件结局、未参与调参的对照和长期评估仍单独验收。


## 冻结调用的复核与结局版本

在单次前向调用详情内登记重大性与簇复核；重大/普通/信息不足复用初筛评估的标签契约，重大必须说明新增量、规模与传导。簇核对为有依据/待核验/有冲突，记录理由，不修改原簇或原调用的准入结果。页面不返回五章模型正文，但其他页面可能已经展示；未见结果、评审者身份均为自述，不能据此认定盲审或独立标签。失败调用也可保留复核，没有冻结主张时不提供事后补造预测的入口。

结局仅对应模型调用前已经冻结的研究主张；其内容、类型、截止日和概率不可在复核接口修改。这些概率来自研究者原有主张，不是五章模型生成的概率。新增调用同时冻结主张历史，已登记结局后重开的主张不能重新算作事前预测；旧调用缺少该历史时保留记录，但不补造历史或放行描述误差。后来的研究编辑、概率修订与材料修订不重算原调用。

结局保留跟踪中、未解决、已兑现、未兑现和部分兑现。独立保存实际事件时点（未知可留空）及服务端登记时刻；事件时点不得在未来，跟踪/未解决时不填写发生时点。兑现、未兑现、部分兑现必须引用已入库新闻/正文的确切版本和逐字引文；服务端核对引用字段、来源指纹、可用时间及有界大小，并冻结原文快照。新闻只支持标题引文，正文沿用不可变材料校验；此校验不能证明引文语义支持结局，也不证明申报时点是真实发生时间。

每次标签或结局更正使用期望版本和请求标识，保存为新的`forward_reviews`行。旧版本、理由、评审者、证据与前一版本指纹保留；冲突和写入失败不覆盖旧记录，相同请求可重试。页面草稿按实例、调用、类别/主张隔离；刷新发现档案版本变化时保留旧草稿并禁止直接保存，明确放弃旧草稿、载入新版后才能重编辑。

只有有效二元结局、判断之后的事件时点、事件时点后可用的证据、有效事前概率、调用前未出现过结局、原输入结构准入通过时，展示单条平方误差`(p/100-y)^2`作为描述值。未知、部分兑现、未解决、旧结局和缺时间一律列出原因而非填0。此处没有把主张数当独立事件数，没有计算模型准确率或总体收益；所有复核仍`forwardEligible=false`。人员独立性、事件实际时点、引用语义、完整真值集、固定窗口的候选比较和长期结局仍需独立验收。


## 固定窗口调用报告

在前向档案中选择一个已冻结基线和已结束的调用窗口[start,end)，冻结该基线在此窗口内全部五章调用。读取不依赖界面最近100条记录，不接受自选run列表或只取成功项。窗口不能早于基线，超过5000次调用或64 MiB明确拒绝，不截断。空窗口生成明确的0次调用报告；来源时点、索引绑定或档案损坏时整次冻结失败，不静默遗漏异常样本。

每份报告保留原基线、全部调用快照、复核历史和结局来源快照、报告源码及指纹。调用范围按原判断时刻，标签/结局取生成报告时已保存版本；生成时刻单列为asOf，不伪装成当时已知的结局。新标签、后来的模型完成/失败或材料更正不改写旧报告；再冻结同一窗口会形成新的报告，相同请求重试只返回原报告。备份恢复保留报告，恢复核对前不接受新冻结。

汇总列出运行状态、输入排除原因、执行依据、标签/簇复核缺失、已知簇/重复调用/未知簇，以及全部冻结主张的未登记、未解决、部分兑现等结局。每簇代表取最早调用（同刻按run ID排序），不按标签、是否成功或结局选择；该列表只供审计，不证明独立事件。单条描述误差沿用冻结复核口径，但不计算跨主张总体误差、模型准确率或收益。报告只涵盖已登记五章调用，暂停登记、尚未送模型的新闻、拆分/语义比较等不在分母；不能据此报告新闻召回率或整体覆盖率。

窗口在事后选择，标签和时点仍非独立真值，因此始终forwardEligible=false。两份报告可能属于不同窗口、不同材料与不同结局成熟度，不能直接相减宣称模型改善；调用前固定的候选配对计划、相同留出输入与独立结局仍是单独要求。

## 同输入的模型配置与提示词对照

`npm run research:compare` 提供独立本机命令行入口，复用五章研判的材料包、提示词、Codex进程、结构/引用校验及失败诊断。它不打开研究数据库，不改变已保存研究或交易。当前对照支持同一源码和输出契约下的两套模型/推理配置，以及两版显式提示词。研判源码候选的独立执行见下方“源码版本对照”。

先准备JSON文件，顶层必须有 `title`、`packets`、`arms`，可另有 `prompts`。`packets` 为现有 `GET /api/research/:id/packet` 导出的完整材料包数组，1–20份、每份最多512 KiB，不重复输入指纹。`arms` 只能有 `baseline` 和 `candidate`；每组必须明确 `binary`（绝对路径）、`model`、`effort`、`timeoutMs`，未提供不同提示词时，两个执行配置不能完全相同；纯提示词实验允许完全相同的执行配置。不要放入密钥或账号配置。

```sh
npm run research:compare -- freeze /absolute/path/spec.json /absolute/path/new-comparison
npm run research:compare -- report /absolute/path/new-comparison
npm run research:compare -- run /absolute/path/new-comparison
```

`freeze` 不调用模型，独占建立全新目录，保存完整材料、逐份实际提示词、双方配置、Codex程序文件指纹、server/shared源码、依赖锁、协议和CLI源码。计划先于全部调用冻结；每份材料由双方各调用一次，最多40次，按材料交替先调用基线/候选以减少固定顺序偏差。没有网页按钮或自动任务。执行 `run` 会使用本机已登录的Codex能力并消耗相应额度；只对显式传入的计划运行。

每次调用前再次核对源码及可执行程序，变化时停止，不用新版本继续旧计划。启动记录先独占写入并同步到文件，结果另存不可覆盖文件。成功输出需通过既有结构/引用校验，并核对模型、推理强度、提示词/schema、材料和输出指纹；普通异常只保留安全错误，Codex失败保留原有trace及有界诊断。取消会停止后续项，未执行项保留分母；每个计划只允许一次执行，不自动重试，重复或并发启动拒绝。终止后如需新的实验，应保留原档案并另建计划，不能把多次实验的最佳结果混成一次。

`report` 只读完整计划的每个槽位，区分候选成功、失败、取消、未开始、已有启动但无结果的“未完成”；文件本身损坏时明确失败，不隐去该项。未完成状态不推断进程已经死亡。统计只给结构通过的完整配对数，不给准确率、总体误差、盈利或自动晋升结论。预选材料不是独立留出或前向样本，账号服务端权重/模型版本及继承环境没有完整冻结；独立标签、共同评价标准、真实结局与长期样本仍须完成。档案含私有材料和模型输出，只保存本地，不随公开源码上传。

五章输出约束另有 `codex-draft-evidence-1` 版本：每次调用从完整材料包生成章节可引用ID枚举，量级核对引用限定为有正文的材料；无对应材料时仅允许空引用数组。保留严格的引用、逐字引文与正文内ID校验，不修补模型的错字，也不改变旧失败结果。提示词正文版本保持独立，实际动态schema指纹随调用trace保存。前向基线记录模板与生成器版本，逐次调用记录实际schema指纹；旧档案按其冻结值读取，新代码不能继续使用旧基线作为未变配置。

不指定实验提示词的模型配置对照格式为 `model-comparison/2`，逐份冻结完整动态schema及其指纹，两组共用同一约束。读取旧 `/1` 档案仍核对原模板指纹，不能用新版代码重新运行旧计划。枚举约束仅减少结构化引用抄错，不保证正文的事实、财务语义或判断正确。


提供 `prompts` 时保存为 `model-comparison/3`。它必须同时指定 `baseline` 和 `candidate`；每个值可为 `null`（当前内置完整提示词）或 `{ "version": "experiment/my-prompt-1", "instructions": "完整的实验研究指令" }`。版本必须以 `experiment/` 开头，后接1–80个字母、数字、点、下划线或连字符，首字符为字母或数字；指令非空且最多64 KiB。指令**替代内置研究指令**，不是在其后追加一句话；因此应完整说明五章顺序、引用、缺口和量级核对要求。输出仍须通过同一动态schema和严格服务端校验，实验不能放宽校验来提高通过数。

应用在实验指令外添加固定的无工具、无交易及不可信材料说明，再原样追加完整JSON材料包；不执行模板插值，不从指令读取路径或载入环境变量。冻结计划保存指令配置及逐输入、逐组的实际提示词全文、版本与指纹。`run` 执行前重新构造并核对提示词，输出trace必须匹配所属组；更改配置、全文、程序或源码必须另建计划。调用隔离、失败分母、独占执行及取消规则与原对照一致。普通工作台的提示词和已保存研判不会因实验改变。

例如，在原有 `title`、`packets`、`arms` 配置中增加：

```json
"prompts": {
  "baseline": null,
  "candidate": {
    "version": "experiment/uncertainty-first-1",
    "instructions": "用中文按顺序输出facts、materiality、companies、scenarios、conditions五章，每章含id、title、paragraphs、sourceIds；引用只能取材料evidence.id。先明确每章未知事项，再写材料支持的判断，区分传闻、事实、假设和反证。不得编造数据或补全未提供正文。missingEvidence列具体核验缺口。materialityReviews逐项覆盖input.materialityReview.targets，按指定schema填targetId、verdict、reason、citations，引用必须逐字来自所选原文；无目标时为空数组。"
  }
}
```

`report` 的 `comparison` 明列执行配置中变化的字段、提示词是否变化及双方版本/逐输入指纹；此类配置/提示词计划的 `sourceChanged` 为false。仅改版本名而全文相同，不算不同提示词。若同时改变模型、推理强度、超时或提示词，不能将结果差异归因于其中一个因素。成功配对只是结构检查通过，不自动选胜者；仍需预先确定共同评价标准、独立盲审和留出样本。旧 `/1`、`/2` 档案按冻结字段只读，不回填新的提示词配置。


## 信号后固定价格窗口（event-prices/2）

封存初筛批次后，在“信号后价格窗口”显式冻结独立报告。保留原整批所有初筛层级及当时标题提及的证券；无证券、身份无效和信息时间矛盾的样本保留原因。不会按当前研究补选证券、按涨跌筛选样本或修改原批次/标注报告。范围是已保存初筛，不等于正式交易信号或全市场事件。

窗口固定为1小时、1/5/20个自然日（每自然日24小时），并非交易日。起点按判断后至少60秒、至多5分钟内的最早有效分钟标签选取；同刻按首次有效快照的接收时间、档案ID及来源键确定。每个终点从同一起点加固定时长，在其后5分钟内选最早同源、同币种、同时间口径的有效标签。缺价或休市不顺延到下个交易日，不前向填充；未到期独立显示。报告保留判断、首次获取、本版可用、目标、实际价格标签及接收时间。

只读取不可变quote_snapshots，逐份校验payload指纹、证券和接收时间，保留隔离及无效快照的检查结果。不使用可改写bars、场景估值或模拟成交价。来源须为现有Eastmoney/Yahoo分钟适配器，市场/币种/未复权/解析质量完整，时间严格有序且时区可解析。始终排除每份快照末柱、经过截断的分钟和接收时尚未经过60秒的标签；出现后续分钟只是已结束观察依据，不证明供应商价格最终定稿或标签等于实际成交时刻。同源同一标签只保留按接收时间及档案ID排序的首次有效观察；后续修订不覆盖它。

event-prices/2对Yahoo明确返回的null价格逐分钟留档。适配器保留原invalidRows计数，并追加missingCloseTimes与原始sourceInterval；连续窗口/异常统计的旧保守判断不变。价格端点评估只有在所有无效项均能一一对应有效整分钟null标签，且标签无重复、无有效价格冲突、不在接收时间之后时，才使用该快照其余合格端点；null不成为价格，不补零、不填充，也不据此认定休市。其他无效价格/时间、字段长度错位、重复或矛盾依然排除整份快照。Yahoo粒度须有原始1m依据；旧档案可使用已保存minuteVolume.interval，无依据时拒绝，不因请求参数为1m就推定响应粒度。缺价标签在archiveDiagnostics中完整保留。旧event-prices/1报告仍按原指纹读取，升级不重算；新报告追加保存新策略版本。

价格变化为`(终点价格/起点价格-1)*100`，输出百分比。可选参照由本次配置显式指定USD/HKD/CNY各一个证券，必须对应同一市场及币种；不默认挑选指数。参照须与研究证券同供应商、同未复权口径、完全相同的起终点时刻，不能用另一个交易日或较晚价格凑齐；参照本身两个端点时区一致。差值为两者百分比相减（百分点），不是因果效应或经独立核验的超额收益。相同证券作为自己的参照不评分。未复权价格未处理分红/拆合股、FX、费用和滑点，不是投资总回报或模拟成交收益。

每个请求在单事务中冻结整批输入、标签、行情档案、可用/排除记录、窗口配置、源码/协议及结果指纹；新报告追加，不更新旧报告。重试相同请求只返回原档案，改参必须使用新请求。时钟早于封存时间、来源指纹异常、源码运行后变化、超过2万快照/20万输入分钟点或64MiB整报告时拒绝，不截断。GET只读，接口不接受客户端价格；恢复副本核对前、离线演示模式禁止新冻结。旧报告随数据库备份保留，重启后按完整指纹读取。

页面按窗口每页50个证券样本显示，并保留总数、无证券样本及全量JSON导出。均保持forwardEligible=false：本次为事后配置、标题身份未独立核验、同簇和转载未证明独立；不汇总成胜率或策略收益。真实行情覆盖、供应商时间含义、基准代表性、公司行动调整、按交易日历的研究和独立前向效果仍单独验收。


## 研判源码版本对照（source-comparison/1）

同一 `research:compare` CLI 可比较两份**已审阅且已安装依赖的本机源码候选**。配置包含 `title`、`packets`、`arms`，另加 `sources: {"baseline": "/absolute/baseline-checkout", "candidate": "/absolute/candidate-checkout"}`；两条路径是项目根目录，不能相同源码重复登记为新候选。两套执行配置可以完全相同。此模式不同时接受 `prompts`：各版本自行调用其 `codexPrompt` 生成提示词；需要实验研究指令时，在候选源码中明确修改并审阅。沿用 `freeze <配置.json> <全新目录>`、`run <目录>`、`report <目录>`。

冻结阶段只准备契约，不调用模型：同一完整材料包交给双方独立Node进程，分别运行各自 `codex-research.mjs` 的包验证、提示词与动态schema生成器。要求候选实现现有五章研判入口（validatePacket、codexPrompt、codexDraftSchema、generateCodexDraft、validateCodexDraft及对应版本字段）；不兼容版本明确失败，不能把新版解析器假装成旧程序。每份材料、每个版本的实际提示词/schema全文和指纹在首次模型调用前固定。源码改动不改变输入材料的选择或内容。

档案保存双方全部server/shared源码、依赖锁、协议、主运行器源码、worker全文、Node版本/程序指纹、Codex程序指纹及已安装node_modules逐文件指纹。依赖目录根部的 `.vite`、`.vite-temp` 是前端临时缓存，明确排除；其他文件和目录内链接纳入，链接必须指向该依赖树内部。整个node_modules根目录可链接到已安装的本机依赖树，记录实际目标；不支持指向树外的单包链接。限制为5万个条目、1 GiB依赖总字节和128 MiB单文件；超限拒绝，不静默省略。计划仍受64 MiB序列化上限约束。

执行时每个槽位在全新子进程中导入自己的源码并调用自己的 `generateCodexDraft`，按样本交替调用顺序，每组每样本一次。调用前后核对源码、依赖、Node/Codex程序与契约，变化时不接受结果或不启动后续槽位。先持久写启动标记，再写不可覆盖的成功/失败记录；并发或重复启动拒绝。取消传递给候选调用并等待进程退出，未启动槽位留在分母。没有结果的启动记录只表示未完成，不凭文件猜测进程已经停止，也不自动重试。

双方输出都需符合当前共同五章/引用校验，且trace绑定各自冻结提示词/schema；改变输出契约以致不兼容时保留失败，不能以放宽评分规则代替改进。报告分列源码、依赖、执行配置、提示词和schema是否变化，供判断混杂因素；不输出自动胜者或质量提升比例。源码与输出档案可在不导入候选代码、无需候选目录的情况下只读检查；继续执行则必须原候选与运行器完整匹配。

**范围与边界：**这是五章研判入口的同材料开发诊断，不运行两版本各自的采集、初筛、材料构造、交易或整套数据库迁移。源码执行仅限已审阅的本机项目代码；独立进程及清理后的环境变量不是任意不可信代码的安全沙箱。候选入口不得自行打开个人库或执行部署。操作系统、代理环境、远端模型权重和服务端状态未完整冻结；独立标签、盲审、真实范围的全流程跨版本覆盖及长期效果仍需另行完成。旧model-comparison档案不改写、不转换。

## 全流程源码对照（pipeline-comparison/1）

`npm run pipeline:compare -- freeze <冻结配方.json> <全新目录>` 固定两份已审阅、已安装依赖的本机源码；`run <目录>` 各运行一次；`report <目录>` 只读。配置严格包含 `title`、`sources`（baseline/candidate项目绝对根路径）与 `recipe`。冻结不读取个人库、不调用模型、不运行候选；运行在各自新建的 `baseline-data/replay.sqlite` / `candidate-data/replay.sqlite` 中，复用各版本的 `createService`、HTTP handler、持久调度器、来源解析器、初筛、材料构造、模型校验、复核和模拟账本。并非只把同一现成材料包交给五章研判器。

配方版本 `pipeline-replay/1`，包含 `seed`、UTC毫秒格式 `startedAt`、`model`、`responses`、`steps`。实验时钟随单调时间线推进；无参数Date及randomUUID仅在子进程内使用冻结时钟和确定序列，原应用不修改。时间和UUID是实验条件，不证明历史真实可用；代码分支改变UUID消耗顺序可造成身份差异，不能将所有差异都归因于业务改善。

- `responses` 每项为 `id/at/url/status/headers/body`，保存原始响应及当时可用时间。仅按精确URL、配方顺序、尚未使用且不晚于当前步骤的响应供给。遗漏、晚到、来源拒绝和原始解析失败保留；没有响应不请求真实网络。原始HTML另行下载而应用读取回执来自其他响应时，不将两者绑定；使用显式保守可用时间，并在私有来源清单注明。HTTP状态/头没有原始回执时注明传输假设，不将正文指纹核对写成完整HTTP响应保真。公开网页复用候选的重定向/URL门禁、提取和日期校验，DNS/TLS为隔离回放中的固定传输替身，不声称验证实际网络或授权可用性。
- `model` 包含 `mode`（`recorded` 或显式 `live-codex`）、一个完整Codex `config`（binary/model/effort/timeoutMs）及 `records`。live模式records必须空，沿用生产Codex生成器并冻结程序指纹；仅这类显式模型调用允许外部模型服务。recorded每项包含 `id/at/lane/contract/result`，lane为research/semantic/material/company。contract绑定完整packetHash、inputHash、实际promptHash、schemaHash、promptVersion、model、effort，以及研究schemaVersion。双方先自己构造包和提示词，使用自己的动态schema生成器或旧版本实际CODEX_DRAFT_SCHEMA常量，不套用新schema；旧录制结果不匹配时明确失败，不改写trace、不编造新版输出。录制结果仍经过各候选的生产结构/引用校验。每次调用另记真实墙钟wallStartedAt/wallFinishedAt；配方at及候选生产trace继续沿用实验时钟，不把其零耗时解释为真实调用耗时。
- 每个 `steps` 项带唯一 `id` 与不回退的 `at`。request提供method/path/body，通过真实HTTP handler在进程内处理，不监听端口；task提供name/action/input，经服务的持久任务接口控制或执行（不调用后台全局tick）；screen运行原初筛，默认返回完整研究快照；可显式设置view为summary，只返回候选实际screenings.stats，逐条修订、初筛及各层级仍完整保存在最终表导出中；market只设置显式冻结的模拟适配输入；wait等待指定模型lane/runId；ingest仅接收显式归档的规范化新闻，不代表验证了原始采集解析。无任意服务方法、SQL、脚本或文件动作。
- path可为字符串片段数组；body等值可用 `{"$ref":"前一步id","path":["字段",0,"子字段"]}` 引用前序成功结果。没有表达式、模糊查找或默认值。前序失败/拒绝/跳过或缺字段时保留依赖失败。市场approve的fingerprint必须为冻结的原始字符串，禁止引用新版review自动补批；版本、风险或行情改变导致拒绝时，原申请和拒绝结果继续留存。

计划包含完整server/shared源码、依赖锁、协议、主驱动/CLI/worker、Node程序和已安装依赖指纹；复用研判源码对照的依赖清单和有界子进程传输。每组前后核对，重复/并发启动拒绝。启动标记先持久保存；取消终止当前进程，后续组不启动；没有结果的启动标记仍为unfinished，不能据此猜测进程已停。独立SQLite及已有记录不自动删除或重试。

结果保存全部步骤输入引用后的实际请求、HTTP拒绝、任务失败/跳过、模型材料/提示词/schema/输出、响应使用与未使用清单、所有SQLite表及行（包括空表和建表定义）。只读报告分别给双方及成对阶段覆盖、全部步骤分母、逐步骤/逐表差异；仅初始化了账本不等于成交，调用模型不等于有效输出。一组completed只表示驱动已完整落档，内部failed/rejected及模型调用完整分母仍必须查看，未写wait步骤也不能隐藏模型失败；只读报告另从冻结news_intake_runs逐条导出入口结果及ok/partial/error/cancelled/interrupted/running完整尝试分母，不改写旧档案。调度步骤成功不代表每个来源成功；CLI遇到任何内部失败/拒绝/未执行/模型失败，以及来源部分、失败、取消、中断或尚在运行时返回非零。不会因不同结果自动选胜者、采纳模型或批准新申请。

边界：配方最多1000步/2000响应/1000录制模型、12 MiB；结果工件64 MiB，完整表导出最多5万行/24 MiB，子进程输出32 MiB。超限明确失败且保留独立库，不截掉失败分母。档案报告不导入候选或打开SQLite，候选目录移走后仍能读；执行则要求原源码和依赖完整匹配。独立子进程不是不可信代码沙箱；运行器仅用于已审阅本机代码。当前固定顺序baseline后candidate，不随机化或声称已排除服务时间漂移。开发回放仍为forwardEligible=false；真实输入覆盖、独立真值、事件时点、留出样本、长期价格/结局和可执行行情仍另行验收。

## 成对事件语义的固定标注诊断

`npm run semantic:evaluate -- freeze <样本.json> <全新目录>` 冻结一个本机Codex执行配置和1–100个成对输入，`run <目录>`执行一次，`report <目录>`只读统计。使用工作台已有`comparisonPacket` / 语义记录中的完整`packet`，复用生产提示词、引用/时间校验和Codex进程，不打开或修改个人研究库。冻结步骤不调用模型；运行会使用本机Codex账号额度。

样本顶层为`title, config, cases`；config字段与research:compare一致。每个case须有`id, clusterId, split, packet, reference`。split为development或holdout；reference须有`relation, reason, reviewer, reviewedAt, origin`，relation沿用七种关系，origin为developer或external-review。参考标签必须在冻结前提供，缺失或未来标注拒收。标签、理由、评审者和分组不进入模型提示词。输入包必须保留阅读范围、版本和输入指纹；材料提供documentId及正文。

计划保存全部源码/协议、命令入口、输入、逐条实际提示词/schema、参考标签、配置和Codex程序指纹。每次调用前后核对源码、契约及程序；计划独占执行，各次启动/成功/失败独立不可覆盖，取消停止后续项。没有结果的启动记录只能说明未完成，不凭文件判断进程存活或重试。未知异常不暴露原始进程信息，结构或引用不符的输出保留失败诊断。旧计划始终保留，不以修改参考标签修饰旧结果。

同一来源对交换方向、升级修订后不能重复计为新案例；已知新闻ID、材料documentId、URL或声明事件簇跨development/holdout会被拒绝。该检查不能发现所有同源转载或同一现实事件，不证明holdout独立。origin同样为提供者声明，external-review不自动获得独立前向资格；全部报告forwardEligible=false。

报告同时显示完整计划分母和成功比较分母：各关系混淆表、逐类精确率、按计划参考标签计算的召回率、误并/漏判计数，并按split、标注来源和事件簇分列。未执行、失败、取消、未完成分别显示，不能从分母删除；零分母为null。参考为类比/无关而输出同事件的计入falseSameEvent；参考为相关/无法判断而输出同事件的另列sameEventDespiteUncertainReference，不把未知真值当确定负例。这些均为预选样本与参考标签的一致性诊断，不是全新闻召回率、真实事实准确率、收益或自动晋升依据。当前命令只评关系类别；主体、动作、因果机制与重大性等语义字段还需独立评审。


## 完整冻结语料的历史召回评估（recall-evaluation/1）

此入口补充预选成对语义诊断：读取工作台导出的 historical-recall/1 或 historical-recall-body/1 报告，评价该报告中**全部非锚点输入**，不只评价已召回候选。完全离线，不打开研究库、不调用模型、不重新运行当前检索算法，不修改旧报告。

在 prototype 目录执行：

```sh
npm run recall:evaluate -- template /absolute/report.json /absolute/new-labels.json
npm run recall:evaluate -- freeze /absolute/report.json /absolute/completed-labels.json /absolute/new-evaluation
npm run recall:evaluate -- report /absolute/new-evaluation
```

template 仅生成待填写表，空字段和 null 不可直接冻结。顶层字段为 title、reportHash、reviewer、reviewedAt、origin（developer 或 external-review）、resultsSeen（明确的布尔值）和 labels。每条标签包含 newsId、newsRevision、relevance（relevant、not-relevant 或 unknown）和非空 reason。相关指“值得作为该锚点的历史机制比较参考”，不等于同一现实事件、可交易机会或获利案例。理由应说明共同业务机制或缺少的证据；不能仅因已经被召回就标为相关。标签必须逐条对应冻结输入的原版本，包括时间无效、较晚、重复以及规则未命中的资料；漏项、重复、未知ID、锚点标注或版本不一致均拒收。reportHash绑定精确报告；修改标签须另存全新评估，原档案保留。

汇总保留 inputs、anchors、evaluated、relevant、notRelevant、unknown 全量分母；selected、truePositives、falsePositives、unknownSelected 是召回集合的计数。knownLabelPrecision=TP/(TP+FP)，unknownSelected 不作为负例；recallOfAllReferences=TP/全部 relevant，未命中和被门禁排除的相关项仍留在分母。两者均为0–1比值，零分母返回 null。falseNegatives 与 missedByStatus 保留漏掉的相关项；mechanismOrContextMisses只计 no_mechanism/no_context，excludedRelevant单列时间/重复/来源门禁排除，不能据此放松门禁。topK按冻结 candidateIds 原顺序取前5/10/25项，少于K时显示实际数，召回率继续使用完整相关参考分母。

报告、标注、统计、源码及命令入口指纹一起保存，目录和文件独占创建，不覆盖既有输出。读取校验报告输入/锚点/版本/逐行状态、候选集合、覆盖计数、摘要及源码内层指纹，再按冻结行和标签重算指标；不会用新版算法重新解释旧检索。每条非锚点输出均保留状态、排名、参考标签和理由。输入最多22000条，文件沿用64MiB档案上限，超限拒绝。指纹用于完整性核对，不证明外部提供者身份或报告真伪；读取不执行所保存源码。

始终 forwardEligible=false：完整语料只指本次提供的冻结输入，不代表全市场覆盖。resultsSeen和origin仅为提供者声明，不能证明独立盲审或真实标签。当前不合并多份报告计分，不将同一资料、发行人或事件簇当作独立样本；跨报告配对比较、独立标签和长期结果仍需另行验证。


### 价格采集计划与价格报告分别留档

price-collection/1显式启用后，对全部新初筛层级登记不可变计划，保存原修订、输入指纹、判断/获取时间、规则、代码/依赖/协议、参照和窗口策略。标签未封存时也可采集，不按成功结局或后来选股补选证券；无证券及准入排除保留在分母。

窗口沿用event-prices/2标签范围与完成观察门槛，另限制接收截止为最后可接受标签后2分钟。窗口状态追加历史，第一次保存的观察不被后续修订替换，迟到行情不能救回旧窗口。容量延后不删除，错过不推断为休市、停牌或价格不动。旧版本计划在新源码下停止，不补造原版本结果。

采集记录不授予独立前向资格、重大性真值或交易成交。封存价格报告仍独立冻结当时完整归档，其回溯读取可能与采集接收截止不同，不得改写采集状态。实际1/5/20日覆盖、基准代表性、独立标签与长期效果仍待验收。

## 免费低频日线价格描述（event-daily-prices/1）

封存批次的价格面板可选择日线或原分钟口径。日线从既有daily_snapshots读取，不新增平台或联网补价；API冻结请求增加basis:"daily"，省略basis仍采用event-prices/2。旧报告按原指纹读取。日线报告是事后价格描述，forwardEligible恒为false，不作为独立研判效果、可成交收益或涨停策略验收。

起点固定为判断时刻所在市场当地日期**之后**的下个交易日收盘，再观察1、5、20个市场交易日。这是显式保守观察约定，不是信号当日成交价。交易日按当前维护的2026日历计数，不按行情行数；起点、目标或日历缺失不顺延。端点价格可算而中间任一收盘缺失时，价格变化保留，收盘最大回撤未知；回撤为窗口内收盘价相对此前最高收盘价的最大负变化，不代表盘中或账户回撤。

来源须保留实际响应的日线粒度和交易所时区（daily-quality/1），并核对证券、币种、价格口径、日历、实际接收时间与档案指纹。旧档案无原始字段时保持未知，不按请求参数补造依据。仅取截止前首次有效已结束收盘；来源报告的窗口内公司行动使对应价格变化未知，供应商复权语义、公司行动完整性及使用权利仍未独立鉴证。参照由操作人显式选择，须同市场、同币种、同源、同口径且同日期；两项变化之差仅为百分点差。

报告追加保存整批样本、标签、来源档案、逐档案诊断、源码/协议、参数与结果指纹；无证券、quiet、亏损、未到期和缺价保留。每日档案可能由历史补采取得，不能据此宣称当时系统已经拥有行情。沿用事务、请求幂等、恢复保护和容量上限，不修改初筛批次、订单或账本。长期独立样本、基准代表性、可执行汇率/费用及真实模拟成交仍待另行验收。
