# 前向研究评估协议 0.3

本轮冻结研究基线；冻结脚本保留持久研究配置，但不采集模型进程环境，不能据此声称已冻结全部实际模型调用配置。不宣布模型有效，不启动自动优化或真实价格成交。既有结构演练账户、回溯案例、附件研判和 9 月 10–24 日测试批次均为开发材料。

## 固定与留出

- 使用 `prototype/scripts/freeze-evaluation.mjs`，以只读事务截取当前研究、历史、正文材料/读取记录、新闻修订及初筛，保存 server/shared 全部规则与本地依赖、依赖锁、当时配置和 SHA-256；输出到被 Git 忽略的 `data/runtime/evaluation/`，按日期、package.json版本和前向协议版本命名，重复执行不覆盖。已冻结的 `baseline-20260925-v09.json` 保留；v0.10 与以后规则独立冻结，不将新版结果混入旧版。v0.8 因遗漏 event-routing 等实际依赖，不再作为完整重放基线；文件保留并由 v0.9 指明替代关系。
- 新时间窗口从北京时间 2026-09-26 00:00 开始，并且不得早于实际冻结时刻。新事件需记录真实首次获取时刻、输入可用时刻、判断时刻、原始输入哈希和规则指纹。缺少任一项只入探索档案。所有日期必须有效且有时区，首次获取 ≤ 本版可用 ≤ 判断，冻结 ≤ 前向起点 ≤ 首次获取。
- 已有主题及其后续发展、同一交易/产品/政策/事故的报道归属同一事件簇。新 ID、新文章或跨市场股票不等于新事件。人工在判断前冻结簇身份；不确定关系标为待定，不纳入独立验证。
- 0.3基线冻结全部活跃/归档事件簇、所有成员历史和当前索引，不限于界面最近记录；同时保存已见研究/历史ID、新闻ID及正文documentId的排除清单。新闻修订、正文修订、事项重新拆分和换新簇ID不产生新样本资格；同一旧正文中的新事项保守地留在探索档案。簇表不完整、快照指纹/历史版本/成员索引不一致时拒绝冻结，不输出不完整清单。
- 前向记录必须附上判断前核验的完整 `clusterMembers`，逐项保留kind、id、revision；material和event另带documentId。缺成员、缺稳定身份、重复成员或命中任一已见来源均拒绝。此函数只校验传入记录，不能独立证明调用者给出的成员覆盖完整或归簇语义正确；服务端登记现绑定不可变成员快照，归簇语义仍须独立复核。
- `forwardEligibility` 执行准入；留出标注不参与调参。旧0.2档案不重写，缺少成员排除清单时不能按0.3放行。候选调参必须形成新版本，使用之后的新窗口及新事件簇验证，不能改写本次基线。
- 服务端可以登记五章研判调用前的输入，但当前尚未自动生成独立合格前向样本。开发候选的簇确认发生在语义模型比较之后；即使早于五章研判，也不能当作独立标签或盲审，不自动进入评估真值。全库自动事件识别仍待完成。

## 标注与档案

重大性标签：重大 / 普通 / 不明确。重大需写出信息增量、影响规模、持续性、财务传导及反证；仅标题含热点词不足。公司关系单列直接、上下游、竞争、同业联动、待核验，不能把同业上涨当盈利证据。

命题、类型和截止日固定后，变更这三项必须新建独立主张；不能沿用旧首次概率评价新问题。结局日期无效、处于未来或早于首次概率判断时刻的记录不得作为成熟结局。

每个主张分别保留事实状态、主观概率、评估时刻、检验日、成立/不成立影响、证据 ID、修订原因及结局。结局为兑现 / 未兑现 / 部分兑现 / 未解决 / 跟踪中。部分兑现和未解决不得强填 0 或 1；未校准概率不得称胜率。

评估档案每条保留 `topicId, clusterId, clusterReviewedAt, clusterMembers, origin, firstSeen, availableAt, decisionAt, inputHash, rulesHash, label, labelReason, reviewer, reviewedAt`。拒绝、失效、未成交、亏损、无信号、误报和漏报均保留，不能只选成功案例。漏报通过独立来源抽样发现并加入档案；当前没有完整真值集，不能报告总体召回率。

## 指标与有效性边界

1. 研究阶段：覆盖率、公司映射准确性、事实与推论分离、反证覆盖、来源可追溯率；同时报告样本数、缺失及标签争议。
2. 概率阶段：仅对有明确二元结局的冻结预测计算 Brier 等指标；按事件簇分组，避免多条转载或多个主张当独立样本。首次概率与修订概率分开。未解决和部分兑现单列，不静默删除。
3. 交易阶段：以后分别计算事件后价格变化、实际模拟成交收益、组合净值；须先确定真实 FX、费用、滑点、交易日/停牌/涨跌停/可卖数量、未成交处理、基准和持有期。当前场景收益不纳入。

样本不足、结局未成熟、输入时间未知、跨期信息泄漏或已见事件簇均需报告原因，不能以短期上涨证明规则有效。本协议包含准入、结局分类与下述回溯诊断指标；真正独立的前向样本和长期结局仍需按本协议积累与验收。


## v0.11 初筛样本入口

`screening_samples` 保存所有层级的标题输入、新闻修订实际可用时间、判断时间、输入指纹、初筛结果与规则指纹；`screening_rules` 保存当时完整初筛依赖文本。重复运行不覆盖旧输入。同一新闻修订后的内容单独留样。

早于该规则启用的首次入库材料记为历史诊断；启用后首次入库单独记为 prospective-intake，但不是本协议的合格 forward-capture。当前没有事件簇排除审查、独立标签或效果统计，因此全部样本 `evaluationEligible=false`。初筛依赖指纹不等同于完整评估基线 `rulesHash`；后续转换需冻结完整基线并重新检查本协议条件，不能直接把两者混用。

人工复核分重大候选、普通资讯、信息不足，保存新增量、相对规模、公司传导、预期差、期限和理由。用户已看到规则结果，故记为非盲审；该标签是研究复核资料，不是独立验证真值，也不将信息不足算作负例。新闻样本数量不等于独立事件数量。


## 冻结批次、隐藏规则标注与描述统计

从“研究评估”建立批次，选择初筛规则指纹和判断时间窗口。窗口为 `[start, end)`，包含该规则在此窗口内保存的全部初筛层级与新闻修订；不接受从浏览器提交自选样本或自制预测。超过 5000 条拒绝创建并要求缩短窗口，不静默截断。数据在同一 SQLite 事务内冻结；后续新闻修订、研究变化与重新初筛不会改写批次。

冻结内容包括标题输入及原始可用时间、当时规则结果、完整初筛规则文本、当前 server/shared 源码及依赖锁、评估协议，以及冻结时刻之前的全部研究主张历史。标题样本只限选定窗口，主张统计则覆盖冻结时的全部研究，两者在界面中明确分开。输入、来源和最终报告各自保存 SHA-256，导出可复核；哈希不防拥有本地数据库写权限者重造整个档案。

封存前，批次详情接口与界面不提供初筛结果、完整规则文本或评分。人工对每条标题标注重大候选 / 普通资讯 / 信息不足、事件簇、评审者、依据和是否此前见过规则结果；重大候选还需新增量、相对规模和公司传导。信息不足也必须留记录，事件簇不明可留空。“此前未见”只是评审者自述；单用户工作台其他入口可能展示过结果，隐藏当前界面不能证明真正独立或盲审。

全部标注完成后，本人显式封存并揭示结果。封存前修改标签生成新版本；封存后原批次不能改写，纠错须另建批次并保留旧报告。重试相同命令幂等，旧版本写入拒绝；恢复副本仍需先通过恢复核对。浏览器草稿按数据集、批次和样本隔离，草稿不替代数据库保存。

### 初筛指标

- 规则 `review` 为阳性，`quiet` / `clue` 为阴性；未知规则结果不当阴性。人工重大为阳性、普通为阴性，信息不足与未标注排除出二元分母，但数量始终列出。
- 同时报告逐条标题的 TP/FP/FN/TN、精确率及**本样本集内**的召回率。分母为零显示不可计算，不显示 0%。没有独立来源真值集，不可外推到所有新闻。
- 事件簇口径只取每簇判断最早的样本；同一时刻按样本 ID 确定。代表选择不看标签或成败，代表标签不明时该簇不进入二元指标；后续修订数量、未知簇和未评分簇另列。这种归组是人工诊断口径，不能证明事件真正独立。

### 概率指标

主张身份（内容、类型、截止日）必须跨版本一致，二元结局需有效时间、理由和结局证据引用；证据获取时间必须不晚于人工结局登记。部分兑现、未解决、缺时间或缺证据不填 0/1。

首次记录概率与人工首次登记结局之前的最后概率分别评分。首次为空不回填后续概率；结局登记时改为 100% 不算预测。曾登记兑现/未兑现/部分兑现再重开后，后续概率不回流成事前预测。只有两种概率都有效的同一批主张才进入配对比较。保留每条纳入/排除记录，以及事实、兑现、盈利、价格主张的分组统计。

Brier 为 `mean((probability / 100 - binaryOutcome)^2)`；分别列出样本数与 5 个固定概率箱（左闭右开，最后一个包含 100%）。分箱和 Brier 都是描述统计：主张可能相关、概率是主观判断，人工结局登记不等于已核验的事件发生时点。因此报告始终 `forwardEligible=false`，不将回溯窗口转换成前向有效性证据，不自动调参或晋升模型。

信号后价格变化和市场模拟收益暂不纳入本批报告。前者缺固定观察窗口及经核验基准，后者缺真实执行适配器与长期样本；页面明确显示不可用，不以原场景账本或短期上涨替代。完整前向标签与结局登记、独立审阅人/来源真值、实际事件时点核验、基线与候选在未参与调参窗口的比较、长期收益归因仍是第 16 项剩余要求。

## 官方历史材料的语义诊断

有限历史案例可以检查事件身份、阶段与引用，但不满足上述前向资格。调用前冻结来源URL、当前获取时间、未改写的提取正文、材料修订、所有配对、参考标签、评分口径、提示词/schema、模型配置及代码快照。标签若由研究助手阅读来源形成，须明确记为助手参考，不能称为独立人工真值或盲审。

使用已有来源读取、材料保存、成对比较和持久模型记录流程；不另写模型提示词或为通过测试缩写正文。来源提取失败、模型失败、无法判断都保留；不看到结果后删样本、改参考标签或自动重试。后来发现参考错误时保留旧版，并建立另一次明确说明原因的诊断。

事件身份主口径：repeat/followup/reversal表示候选同一事件，related/analogy/unrelated表示未归为同一事件，uncertain单列为弃权。这是有限诊断的操作性分组，不表示related已经证明客观上属于不同事件。阶段类别另按预先声明的可接受集合核对，未知及失败不进入成功分子。逐字引用检查仅证明引用存在，仍须逐项阅读主体、对象、阶段和时间是否得到输入支持。

逐对结果必须同时给出独立事件家族数，复用材料的配对不能视为相互独立样本。著名历史事件可能已在模型训练资料中，英文公司公告也不能代表A/H中文新闻、传闻、多事件长文或日常分布。无论结果如何均保持`forwardEligible=false`，不据此计算全市场准确率、晋升模型、自动合并或启动交易。

公开审阅只包含来源链接、日期、指纹、预先声明的口径和各次结果元数据；第三方正文及带原文引用的模型输出只在本地评估档案留存。原始读取结果、输入、运行记录和代码快照用文件清单及SHA-256核验，版本升级不覆盖旧档案。首轮清单见[官方材料语义诊断](evaluations/semantic-official-20261003.json)，执行状态仍以[任务清单](BACKLOG.md)为准。

## 服务端前向调用登记

在“研究评估 → 前向调用档案”显式冻结新基线后，后续手动和自动五章研判共享同一登记钩子。冻结本身不调用模型；默认不启用，可以暂停新登记。新基线不会改写旧基线，重试相同请求返回原记录，不会重新启用已暂停或被替代的基线。恢复副本核对前拒绝冻结和模型调用。

基线保留本协议0.3的全部排除档案，并保存服务端指定的本机Codex路径、模型、推理强度、超时、提示词版本和schema指纹；不保存凭据或继承的进程环境，也不以二进制路径证明程序内容不变。冻结核对当前源码与模块加载时指纹，文件在运行中变化时需重启候选服务后重新冻结。现有基线发生代码或模型配置变化时，后续记录保留但标为排除。

模型run、材料包指纹、研究版本、输入指纹、事件簇当前完整成员快照、来源获取/可用时间、规则与执行依据，以及自动队列关联/租约在同一写事务登记；任何存储失败全部回滚，模型尚未调用。客户端只提交基线名称和请求标识，不能自填成员、首次获取时间或模型参数。原模型run保留完整材料包和结果，前向档案通过指纹绑定读取；后续编辑、归档、模型采纳、暂停及基线切换不重算旧登记。

每次五章研判都留记录，输入准入只检查可证明的结构条件。未完整绑定单一有效簇、来源时间无法核实、旧来源对照、研究已调用过、代码/模型变化均保留具体原因。同一簇或任一稳定来源已在之前的前向调用中出现时，后续研究ID、簇ID或来源修订不能再次计为新输入；首次失败和排除记录也参与去重，不按成功与否挑选。

查询重新核对基线/档案指纹、完整材料包、模型run、原始输出和实际执行trace。输入准入、档案关联完整性和实际执行依据分别展示；失败或未完成调用可能没有完整trace，不自动解释为模型成功。所有登记仍为 `forwardEligible=false`，尚无独立标签、结局和效果验收。记录覆盖五章研判，不代表拆分、语义比较、身份识别的独立评估。

基线和调用档案进入SQLite备份；页面展示最近50个基线及100次调用并同时给出总数，旧记录不删除，可按ID读取。指纹用于发现意外不一致，不防具有数据库写权限的人重造整个档案。标签、实际事件结局、未参与调参的对照和长期评估仍单独验收。


## 冻结调用的复核与结局版本

在单次前向调用详情内登记重大性与簇复核；重大/普通/信息不足复用初筛评估的标签契约，重大必须说明新增量、规模与传导。簇核对为有依据/待核验/有冲突，记录理由，不修改原簇或原调用的准入结果。页面不返回五章模型正文，但其他页面可能已经展示；未见结果、评审者身份均为自述，不能据此认定盲审或独立标签。失败调用也可保留复核，没有冻结主张时不提供事后补造预测的入口。

结局仅对应模型调用前已经冻结的研究主张；其内容、类型、截止日和概率不可在复核接口修改。这些概率来自研究者原有主张，不是五章模型生成的概率。新增调用同时冻结主张历史，已登记结局后重开的主张不能重新算作事前预测；旧调用缺少该历史时保留记录，但不补造历史或放行描述误差。后来的研究编辑、概率修订与材料修订不重算原调用。

结局保留跟踪中、未解决、已兑现、未兑现和部分兑现。独立保存实际事件时点（未知可留空）及服务端登记时刻；事件时点不得在未来，跟踪/未解决时不填写发生时点。兑现、未兑现、部分兑现必须引用已入库新闻/正文的确切版本和逐字引文；服务端核对引用字段、来源指纹、可用时间及有界大小，并冻结原文快照。新闻只支持标题引文，正文沿用不可变材料校验；此校验不能证明引文语义支持结局，也不证明申报时点是真实发生时间。

每次标签或结局更正使用期望版本和请求标识，保存为新的`forward_reviews`行。旧版本、理由、评审者、证据与前一版本指纹保留；冲突和写入失败不覆盖旧记录，相同请求可重试。页面草稿按实例、调用、类别/主张隔离；刷新发现档案版本变化时保留旧草稿并禁止直接保存，明确放弃旧草稿、载入新版后才能重编辑。

只有有效二元结局、判断之后的事件时点、事件时点后可用的证据、有效事前概率、调用前未出现过结局、原输入结构准入通过时，展示单条平方误差`(p/100-y)^2`作为描述值。未知、部分兑现、未解决、旧结局和缺时间一律列出原因而非填0。此处没有把主张数当独立事件数，没有计算模型准确率或总体收益；所有复核仍`forwardEligible=false`。人员独立性、事件实际时点、引用语义、完整真值集、固定窗口的候选比较和长期结局仍需独立验收。


## 固定窗口调用报告

在前向档案中选择一个已冻结基线和已结束的调用窗口[start,end)，冻结该基线在此窗口内全部五章调用。读取不依赖界面最近100条记录，不接受自选run列表或只取成功项。窗口不能早于基线，超过5000次调用或64 MiB明确拒绝，不截断。空窗口生成明确的0次调用报告；来源时点、索引绑定或档案损坏时整次冻结失败，不静默遗漏异常样本。

每份报告保留原基线、全部调用快照、复核历史和结局来源快照、报告源码及指纹。调用范围按原判断时刻，标签/结局取生成报告时已保存版本；生成时刻单列为asOf，不伪装成当时已知的结局。新标签、后来的模型完成/失败或材料更正不改写旧报告；再冻结同一窗口会形成新的报告，相同请求重试只返回原报告。备份恢复保留报告，恢复核对前不接受新冻结。

汇总列出运行状态、输入排除原因、执行依据、标签/簇复核缺失、已知簇/重复调用/未知簇，以及全部冻结主张的未登记、未解决、部分兑现等结局。每簇代表取最早调用（同刻按run ID排序），不按标签、是否成功或结局选择；该列表只供审计，不证明独立事件。单条描述误差沿用冻结复核口径，但不计算跨主张总体误差、模型准确率或收益。报告只涵盖已登记五章调用，暂停登记、尚未送模型的新闻、拆分/语义比较等不在分母；不能据此报告新闻召回率或整体覆盖率。

窗口在事后选择，标签和时点仍非独立真值，因此始终forwardEligible=false。两份报告可能属于不同窗口、不同材料与不同结局成熟度，不能直接相减宣称模型改善；调用前固定的候选配对计划、相同留出输入与独立结局仍是单独要求。
